Chapter 13 The 50 Questions

Fifty questions you will be asked — in interviews, design reviews, Slack channels, and your own head at 2 AM. Concise answers with snippets when the right answer is code.

Concepts

In one sentence: CI vs CD?

CI validates every change on a shared branch with automated build + tests; CD packages (Delivery) or releases (Deployment) every change that passes CI.

What's the difference between a pipeline and a workflow?

They're the same idea; different tools picked different words. Jenkins says "pipeline"; GitLab says "pipeline"; GitHub Actions says "workflow". All mean: one end-to-end run containing jobs and stages.

What are DORA metrics and why do they matter?

Deployment frequency, lead time for changes, change failure rate, and mean time to recovery. They correlate strongly with team performance and business outcomes per Google's DORA research. Good CI/CD moves all four in the right direction.

What's a dependency graph in pipeline terms?

The graph of jobs where an edge means "this job needs this other job's output". Tools vary in how much of the real graph they let you express — stages (waterfall) vs needs (DAG).

Artifact vs cache?

Artifact: required for downstream jobs; persisted with retention; pipeline-scope. Cache: optional speed-up; best-effort; key-scoped across pipelines.

Why is trunk-based development associated with CI/CD?

Small, frequent merges to main is what enables CI to catch problems early and CD to always have a shippable main. Long-lived feature branches break this.

What's a "flaky" test and how do you deal with it?

A test that passes sometimes, fails sometimes, with the same code. Options: fix the flake (best), retry N times automatically (retry in all three tools), quarantine to a non-blocking suite, or remove entirely. Accepting flakes erodes trust in the whole pipeline.

Jenkins

Controller vs agent?

The controller schedules jobs and holds config/state; agents execute the work. In production, agents are where builds run — the controller should rarely run builds itself.

Freestyle vs Pipeline?

Freestyle is UI-configured, stored in Jenkins, brittle. Pipeline is code in a Jenkinsfile, in your repo, reviewable, rollbackable. Use Pipeline.

Scripted vs Declarative Pipeline?

Scripted is raw Groovy (node { ... }). Declarative is a constrained DSL (pipeline { agent … stages { ... } }). Declarative is the default for new work; falls back to script { ... } when you need imperative Groovy.

Why should I use a Shared Library?

To factor common pipeline logic out of every Jenkinsfile. Define steps/templates once, version them in git, pin consumers to tags. The only way to keep 50 Jenkinsfiles consistent.

What does agent none mean?

Don't allocate an agent at pipeline scope — require each stage to declare its own agent. Useful for "wait for input" stages that shouldn't hold an executor, or for mixing Linux/Windows stages.

Why @, -, and + on recipe/step lines? (GNU Make analogue)

Different: Jenkins doesn't have these. You get similar capability via sh(label: '...', returnStatus: true), catchError, and the various options. Fail-fast vs continue is controlled by post or catchError.

How do I run a pipeline locally before pushing?

Closest: Replay feature on an existing build (lets you edit and re-run). For linting, use the jenkins-cli declarative-linter or the Jenkinsfile Runner container. True local runs are awkward — another reason to prefer simpler Jenkinsfiles.

How do you parallelise in Declarative Pipeline?

parallel { stage('A') { ... }; stage('B') { ... } } within a stage. Add failFast true to stop all branches when one fails.

How do you share files between stages?

stash name: 'foo', includes: '...' and unstash 'foo'. For persistence beyond the pipeline, use archiveArtifacts.

What is Jenkins Configuration as Code (JCasC)?

A plugin that lets you define the entire Jenkins controller config in YAML. Applied on startup. Brings Jenkins config into git, reviewable and rollback-able.

Why pin shared library versions?

Because live-at-HEAD libraries mean a bug in the library breaks every consumer at once. Pin with @Library('name@v1.2.0') or a commit SHA; upgrade deliberately.

How do I handle credentials safely in a Jenkinsfile?

Use withCredentials([...]) with single-quoted shell strings so Groovy doesn't interpolate the secret into the command line. Or bind via environment { credentials('id') } when you want the value available across the whole block.

What's a multibranch pipeline?

A Jenkins project that scans a git repo and creates a sub-job per branch/PR that has a Jenkinsfile. Auto-builds every branch and MR/PR. Default choice for any serious project.

GitLab CI

What are runners?

The worker processes that execute jobs. GitLab schedules, runners pull and run. Scopes: instance/shared, group, project. Executors: shell, docker, kubernetes, ssh, vm, custom.

What are the default stages?

.pre, build, test, deploy, .post. Override with the top-level stages: list.

rules vs only/except?

rules is the modern replacement — supports if, changes, exists, when, variables, all in one list evaluated top-to-bottom. Don't mix with legacy only:/except:.

What's needs:?

Declares a job's specific prerequisites, converting the default stage-waterfall into a DAG. A job with needs: starts as soon as its named prereqs finish, skipping ahead of other jobs in the same stage.

What's a dynamic child pipeline?

A job that generates a YAML pipeline file (from script) and triggers it via trigger: { include: { artifact: generated.yml, job: ... } }. Great for monorepos — generate only the jobs relevant to changed paths.

What's the integrated container registry?

Every GitLab project has a built-in Docker registry reachable at $CI_REGISTRY_IMAGE. Authenticate with $CI_REGISTRY_USER/$CI_REGISTRY_PASSWORD — both auto-injected.

How do I avoid duplicate pipelines on MRs?

Workflow rules that skip branch pipelines when an MR exists:

workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH && $CI_OPEN_MERGE_REQUESTS
      when: never
    - if: $CI_COMMIT_BRANCH
What's the difference between include and extends?

include pulls in an external YAML file. extends inherits fields from another job in the same file (or included via include). They compose — you extend jobs defined in included files.

Environments in GitLab?

Named deploy targets (staging, production, PR-123) attached via environment: { name, url }. GitLab tracks deploys per env, supports rollback, and (on paid tiers) review apps (dynamic environments per MR).

What's a Merge Train?

Premium feature. When multiple MRs are ready, GitLab queues them, rebases each onto the prior, tests the combined result, and merges only if each combined pipeline passes. Eliminates "green alone, red together" bugs.

CI/CD Components vs include:?

Components are a newer, more structured way to share CI logic: versioned, with explicit inputs declared in spec.inputs, discoverable via the CI/CD Catalog. Prefer them for new reusable logic; include: for quick-and-dirty sharing.

GitHub Actions

Workflow vs job vs step vs action?

Workflow = .github/workflows/*.yml. Job = runs on one runner. Step = one unit inside a job, either run: (shell) or uses: (action). Action = a reusable step distributed as a git repo.

What's the marketplace?

A public directory of Actions and Workflows others have published. Most have sources on GitHub. Extremely useful; pin untrusted ones by SHA.

GitHub-hosted vs self-hosted runners?

Hosted: ephemeral VMs provisioned by GitHub (free tier + paid); zero maintenance. Self-hosted: your machines polling GitHub; required for private networks, special hardware, or heavy usage economics.

What's GITHUB_TOKEN?

A short-lived token auto-injected into every workflow run. Default permissions are broad — lock them down per-workflow with permissions: {...}.

Reusable workflows vs composite actions?

Reusable workflow wraps jobs (full-runner unit). Composite action wraps steps (inlined inside a caller's job). Pick by scope.

How do I skip a run?

Commit message with [skip ci] (many hosts recognise this). Or paths-ignore: on the trigger. Or a first job that checks and bails with if: ....

Matrix include/exclude?

exclude drops cells from the cartesian grid. include adds cells (or extra vars to existing cells). Let you customise without expanding the full matrix.

What's concurrency + cancel-in-progress?

Groups runs by a key (usually ${{ github.ref }}). With cancel-in-progress: true, a new run cancels the earlier one — saving runner minutes on rapid pushes.

How do I trigger a workflow from another workflow?

Three ways: workflow_call (reusable workflows), workflow_run (chain after another workflow completes), or repository_dispatch (external API).

How do I dynamically compute a matrix?

One job emits a JSON array to $GITHUB_OUTPUT; a later job uses strategy: matrix: ${{ fromJSON(needs.first.outputs.values) }}.

Security & ops

Why OIDC?

To eliminate long-lived cloud credentials from CI. Each job exchanges a short-lived JWT (signed by the CI system) for a cloud credential via the cloud's IAM, scoped by claim (repo, branch, environment).

How do I pin a third-party action safely?

By full commit SHA, not tag: uses: some-org/some-action@a1b2c3.... Dependabot can keep the pin updated via reviewable PRs.

What's an SBOM?

Software Bill of Materials. Machine-readable list of components in an artifact (direct and transitive deps). Generate with syft, cyclonedx-*, language-specific tools. Ship alongside releases.

What's SLSA?

A framework of four levels describing build-provenance integrity, from "some metadata" (L1) to "hermetic, deterministic, two-person-reviewed" (L4). Common aspiration: SLSA 3, reachable for most teams via GitHub attestations + signed artifacts.

Why never store long-lived cloud keys?

Because a leak = weeks of exposure while you notice and rotate. Short-lived (OIDC, STS) reduce blast radius to minutes. Plus, fewer places for secrets = less surface area.

How do you prevent secrets from leaking into logs?

Never echo them. Use env vars (all three tools mask literal values). Don't transform them (base64/hash defeats masking). Prefer file-type secrets for CLIs. Turn on secret scanning so you detect when one sneaks through.

What's the "fork PR problem"?

An external fork PR can modify the pipeline file itself; running that pipeline with full secrets and deploy access = supply-chain compromise. Mitigate: forks don't get secrets by default; require manual approval for first-time contributors; keep deploy steps gated by branch + environment approvals.

Decision-making

When should I self-host runners?

Three reasons: private-network access, specialty hardware (GPUs, macOS in bulk, specific OS versions), or cost (at >$5k/month of SaaS minutes, self-hosted on spot instances usually wins). Otherwise stick with SaaS.

If I had to pick one in 2026 for a green-field startup on GitHub?

GitHub Actions. Zero ops, free tier is generous, the marketplace covers every integration you'll reach for, OIDC-to-cloud is easy, and if you outgrow it you can add self-hosted runners or escape-hatch to Buildkite/CircleCI for specific workloads. Only reach for Jenkins if a specific requirement forces it.

Bonus: ten more that come up

What's the 10-minute CI budget and why?

Developers context-switch after ~10 minutes of waiting. Pipelines slower than that push people toward "push and pray" rather than "test locally, commit small". Under 10 min for the fast-feedback path; longer for nightly/release pipelines is fine.

Blue/green vs canary deploy?

Blue/green: two identical environments, switch traffic atomically. Canary: gradual rollout (1% → 10% → 100%) with health checks. Blue/green is safer for small apps; canary gives richer feedback on larger ones.

How do I run a step only on schedule?

In all three: condition on the trigger. GHA: if: github.event_name == 'schedule'. GitLab: if: $CI_PIPELINE_SOURCE == "schedule". Jenkins: when: triggeredBy 'TimerTrigger' (or check currentBuild.getBuildCauses()).

What's a "pipeline-as-code" anti-pattern you see?

Using CI as a scripting host for arbitrary tasks — cron-like utility scripts that don't actually validate code. If a "job" isn't part of your build-or-release flow, it belongs in a scheduler (Airflow, CronJobs), not the CI.

Where should integration tests run?

In CI, but after unit tests (fast-fail), and ideally in parallel. Gate on their success before publish/deploy. If they're flaky, fix them before accepting their red/green as reliable signal.

How do I handle secrets for local development?

A separate dev-secret file excluded from git (.envrc, direnv, macOS Keychain, 1Password CLI). Never share the CI's secrets with local devs — different blast radius, different rotation cadence.

Why does my matrix cell take so long in GHA?

Typical culprits: cache miss, container pulls, actions/checkout with full fetch-depth. Fixes: explicit cache:, fetch-depth: 1 unless you need more, self-hosted runner with warm image cache.

How do I deal with monorepo pipelines?

Detect changed paths in job-0, then either (a) skip jobs whose paths didn't change, or (b) generate a dynamic pipeline with only the relevant jobs. GitLab's dynamic child pipelines and GHA's fromJSON matrix are the main tools.

What's a "deploy freeze"?

A period when production deploys are prohibited (holidays, big-launch weekends, on-call handoffs). Implement as a check that fails the pipeline during those windows — policy as code, visible to humans.

If my CI goes down, what's my plan?

Depends. If it's a SaaS outage: wait it out, or trigger manual deploys via the cloud CLI from an on-call's laptop. If it's self-hosted: have runbooks for restore-from-backup, pre-provisioned standby controller, and tested scripts to push emergency releases without CI. Document the plan; practice it.
