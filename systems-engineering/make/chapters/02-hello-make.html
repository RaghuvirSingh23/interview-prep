Chapter 02 Hello, Make

Time to write something. In this chapter you'll install Make, write your first Makefile, and meet the single most infamous gotcha in the entire tool — the tab character. By the end, you'll have a working build that rebuilds only what it needs to.

Installing GNU Make

You almost certainly have some version of make already. This tutorial assumes GNU Make 4.0 or newer. Check: 

$ make --version
GNU Make 4.4.1
Built for x86_64-pc-linux-gnu
Copyright (C) 1988-2023 Free Software Foundation, Inc.

If the banner doesn't say "GNU Make", or the version is under 4.0, install it.

macOS

Apple ships GNU Make 3.81 (from 2006!) because of a licence change. Install the modern one via Homebrew: 

$ brew install make
$ gmake --version                    # note: "gmake", not "make"
GNU Make 4.4.1

Homebrew installs it as gmake to avoid colliding with system make. Through this tutorial I'll say make; if you're on macOS with Homebrew, substitute gmake mentally, or add this to your shell rc: 

alias make=gmake

Linux

Already installed on every distro. Upgrade if you're on something ancient:

$ sudo apt install make         # Debian/Ubuntu
$ sudo dnf install make         # Fedora
$ sudo pacman -S make           # Arch

Windows

Use WSL. You'll have a real Linux with a real Make. Native Windows has nmake (Microsoft's variant) but this tutorial is about GNU Make specifically.

Not all makes are GNU Make

BSD systems (OpenBSD, FreeBSD, NetBSD, and macOS) ship a different implementation called BSD Make. Its syntax for anything beyond the most basic rules is different. A Makefile written for GNU Make will often fail on BSD Make, and vice versa.

GitHub repos that say make ... in their README almost always mean GNU Make. If you hit baffling parse errors on macOS, it's probably because you're invoking the old BSD-ish stub. Switch to gmake.

Your first Makefile

Create an empty directory:

$ mkdir -p ~/learning-make/ch02 && cd ~/learning-make/ch02

Create a file named exactly Makefile (capital M, no extension) with this content:

makeMakefile
hello:
	echo "Hello, Make!"
The line starting with echo MUST begin with a TAB

Not four spaces. Not two spaces. Not a mix. A single literal tab character. If your editor inserts spaces, find the "show whitespace" option and turn it on. If your editor is VS Code, make sure the tab width is a tab for *.mk / Makefile.

Why? Feldman himself called this "the Make braindamage". He wanted recipes to be visually distinct from target lines, so he required a tab. He has said publicly he'd fix it if he could, but by the time it was clearly a mistake there were already too many Makefiles in the world. We're stuck with it.

If you get Makefile:2: *** missing separator. Stop. — that's your tab-vs-spaces mistake.

In this tutorial, tabs at the start of recipe lines are rendered as a grey → glyph so you can see them. When you copy a code block, the copy button replaces the glyph with a real tab.

Now run it:

$ make
echo "Hello, Make!"
Hello, Make!

Two lines of output. Make echoes each recipe line before running it (that's the first line), then shows the output of the command (the second line). You can silence the echoing with @ — more on that in Chapter 3.

A slightly more real build

Let's do the C build from Chapter 1 for real. We need three trivial source files.

cmain.c
#include <stdio.h>

void greet(const char *who);

int main(void) {
    greet("world");
    return 0;
}
cgreet.c
#include <stdio.h>

void greet(const char *who) {
    printf("Hello, %s!\n", who);
}

And the Makefile:

makeMakefile
hello: main.o greet.o
	cc main.o greet.o -o hello

main.o: main.c
	cc -c main.c -o main.o

greet.o: greet.c
	cc -c greet.c -o greet.o

clean:
	rm -f hello main.o greet.o

Now try this sequence:

$ make
cc -c main.c -o main.o
cc -c greet.c -o greet.o
cc main.o greet.o -o hello
$ ./hello
Hello, world!
$ make
make: 'hello' is up to date.
$ touch greet.c
$ make
cc -c greet.c -o greet.o
cc main.o greet.o -o hello

Read this carefully. It demonstrates the whole point of Make:

  • First make: builds everything from nothing.
  • Second make: nothing to do — files are up to date.
  • After touch greet.c: Make notices greet.c is newer than greet.o, rebuilds greet.o, notices hello's prerequisites changed, relinks. Does not recompile main.c.

Try it. Then type make clean and watch it remove the outputs.

How to invoke Make

$ make                    # build the default goal (first target)
$ make hello              # build a specific target
$ make clean              # run a target named "clean"
$ make hello clean        # several goals, one after the other
$ make -f build.mk        # use a different file (not "Makefile")
$ make -j 4               # parallel: up to 4 jobs at once
$ make -n                 # DRY RUN: print what would run, don't execute
$ make -B                 # force a full rebuild (ignore timestamps)
$ make -s                 # silent: don't echo recipes
$ make --debug=basic      # show Make's decisions
$ make VAR=value          # override a variable from the command line

The ones you'll use 99% of the time are make, make clean, make -j, and occasionally make -n when something looks off.

Which files Make reads

When you run make, it looks (in order) for:

  1. GNUmakefile
  2. makefile
  3. Makefile

Almost everyone uses Makefile. The GNUmakefile name is useful only when you want your Makefile to be ignored by BSD Make and picked up only by GNU Make. You can also force a specific file with -f: 

$ make -f debug.mk

Includes other than the three above are found via include directives inside the Makefile — we'll meet those in Chapter 8.

Comments and line continuations

Comments start with #. They go until end-of-line.

# This is a comment.
hello:       # so is this
	echo hi  # this is passed to the shell as "echo hi  "; the shell sees the #

Long lines can be continued with \ at end-of-line. Make strips the backslash, replaces the newline with a space, and joins the next line: 

SOURCES = main.c \
          greet.c \
          util.c

Echo and silence

By default, Make prints each recipe line before executing it. This is good for debugging, annoying for polished builds. Three ways to suppress: 

hello:
	@echo "quiet — the @ tells Make not to echo this line"
	echo "loud — this line is echoed"

You can also pass -s on the command line, or add .SILENT: as a special target:

.SILENT:
hello:
	echo "this would be silenced despite no @"

Most hand-written Makefiles are loud. You want to see what's being run. Reserve @ for echo lines that print human-readable status: 

hello: main.o greet.o
	@echo "  LINK   hello"
	cc main.o greet.o -o hello

Exit status and error handling

Each recipe line is run in its own subshell. If any line exits non-zero, Make stops and prints: 

$ make
false
make: *** [Makefile:2: hello] Error 1

This is what you want. If you deliberately want to ignore the exit status of a line, prefix it with -:

clean:
	-rm -f hello main.o greet.o

Without the -, rm -f is already OK because -f makes it never fail — but as an illustration, the leading - tells Make "I don't care if this command fails". Use sparingly.

Hands-on: feel the laziness

Hands-on · do this now

1. Still in ~/learning-make/ch02, make sure you have the main.c, greet.c, and Makefile from above. 

$ ls
Makefile  greet.c  main.c

2. Build twice. The second build should do nothing.

$ make
cc -c main.c -o main.o
cc -c greet.c -o greet.o
cc main.o greet.o -o hello
$ make
make: 'hello' is up to date.

3. Touch only main.c. Predict what will rebuild. Then run make to check.

$ touch main.c
$ make
cc -c main.c -o main.o
cc main.o greet.o -o hello

It rebuilt main.o (because main.c is newer) and relinked hello (because main.o is newer than hello), but skipped greet.o. Good.

4. Now touch the binary itself and watch what happens.

$ touch hello
$ make
make: 'hello' is up to date.

hello is now newer than all its prerequisites, so Make is satisfied. This is exactly what you'd expect from a pure timestamp model — and exactly the "bug" from Exercise 1.3.

5. Clean up and re-check.

$ make clean
rm -f hello main.o greet.o
$ ls
Makefile  greet.c  main.c

Exercises

EX 2.1 easy Deliberately break the tab rule

Edit your Makefile and replace the tab before the cc main.o greet.o -o hello line with four spaces. Save. Run make clean && make. What error do you get?

Show solution 
$ make
Makefile:2: *** missing separator.  Stop.

Make sees a recipe line that isn't tab-indented, concludes that it must be a malformed rule, and bails. This error message has probably wasted more collective human lifetime than any other in computing. Memorise what it means: spaces where a tab should be.

EX 2.2 easy Change the default goal

In the current Makefile, the first target is hello, so make by itself builds it. Rearrange the file so that clean is the first target. Then type make with no arguments. What happens?

Show solution

Make will run clean. Almost certainly not what you want — which is why clean is conventionally near the bottom of a Makefile, not the top. If you really want a specific target to be the default regardless of position, set the .DEFAULT_GOAL variable: 

.DEFAULT_GOAL := hello

clean:
	rm -f hello main.o greet.o

hello: main.o greet.o
	cc main.o greet.o -o hello

# … etc

Now make with no args builds hello, even though clean appears first.

EX 2.3 easy Add a third source file

Add a new file farewell.c that defines void farewell(const char *who) printing "Goodbye, NAME!". Call it from main. Update the Makefile so make builds everything. Don't copy the existing rules blindly — think about what rules the new file needs.

Show solution
cfarewell.c
#include <stdio.h>

void farewell(const char *who) {
    printf("Goodbye, %s!\n", who);
}
cmain.c (updated)
void greet(const char *who);
void farewell(const char *who);

int main(void) {
    greet("world");
    farewell("world");
    return 0;
}
makeMakefile
hello: main.o greet.o farewell.o
	cc main.o greet.o farewell.o -o hello

main.o: main.c
	cc -c main.c -o main.o

greet.o: greet.c
	cc -c greet.c -o greet.o

farewell.o: farewell.c
	cc -c farewell.c -o farewell.o

clean:
	rm -f hello main.o greet.o farewell.o

Notice how repetitive this is. By Chapter 5 we'll replace all four compile rules with one pattern rule.

EX 2.4 medium Dry-run and force-rebuild

Without modifying any files, use make -n to see what Make would do if one particular file were out of date. Hint: you can't make Make "pretend" a file is stale with -n alone — but you can combine it with -W (--what-if). Look up what -W does and use it to ask "what would happen if I touched greet.c?"

Show solution

make -W file tells Make to pretend file was just modified, without actually touching it. Combine with -n and you get "dry-run: what would happen if this file changed?": 

$ make -n -W greet.c
cc -c greet.c -o greet.o
cc main.o greet.o farewell.o -o hello

No files touched. No commands run. But you now know that modifying greet.c would trigger exactly those two steps. This is golden for sanity-checking complex Makefiles before a big edit.

EX 2.5 medium Observe parallelism

With a clean tree (make clean), run make and note the order of the .o compilations. Then run make clean && make -j 4. Does the order change? Why?

Show solution

Without -j, recipes run sequentially in the order Make discovers them during the graph walk (depth-first from the root goal). You'll typically see main.o, then greet.o, then farewell.o, then the link.

With -j 4, the three compilations are independent of each other — none depends on another — so Make schedules them to run concurrently. The interleaved output may look messy. The link step must wait until all three .os are present, because the link rule lists them as prerequisites.

This is the payoff of Make's declarative model: you told it what depends on what, and it figured out when.

EX 2.6 hard What happens with a missing source?

rm greet.c. Now make clean && make. What error do you get, and at what stage? Why doesn't Make notice before running the first compilation? (Hint: it's about the order of graph traversal.)

Show solution 
$ make clean
rm -f hello main.o greet.o farewell.o
$ make
cc -c main.c -o main.o
make: *** No rule to make target 'greet.c', needed by 'greet.o'.  Stop.

Make does notice before running the compile for greet.o — but by then, main.o has already been built. That's because Make walks the graph and schedules work as it goes. Without parallel execution, it starts with the first prerequisite of the root (main.o), realises it's achievable, runs it, and only then moves to the second prerequisite (greet.o) which depends on a file that doesn't exist.

Lesson: Make's error detection for missing files is lazy. It doesn't pre-validate the whole graph.

Side note: in parallel mode (-j), Make may have started multiple compilations before hitting the error. You'll still get the "No rule to make target" error, but your output ordering will be interleaved.

Recap

  • Makefiles are named Makefile (or GNUmakefile, or whatever you pass to -f).
  • Every recipe line begins with a literal tab — not spaces. missing separator is tab-vs-spaces.
  • Each recipe line runs in its own subshell. Non-zero exit halts the build unless you prefix the line with -.
  • Make prints each recipe line before running. Prefix with @ to silence just one; use -s or .SILENT: globally.
  • Useful CLI flags: -n (dry run), -W file (pretend file is fresh), -B (force rebuild), -j N (parallel).
  • The first target in the file is the default goal, unless you set .DEFAULT_GOAL.
