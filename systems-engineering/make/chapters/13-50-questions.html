Chapter 13 The 50 Questions

50 questions you will be asked about Make — in interviews, code reviews, Slack channels, and the back of your own mind at 2 AM. Each one gets a concise answer with a code snippet where relevant. Treat this chapter as a reference you'll come back to.

Fundamentals

What does Make actually do in one sentence?

It walks a dependency graph of files, comparing filesystem timestamps, and runs the recipe for any target whose prerequisites are newer than it (or which doesn't exist).

What's the difference between Make and a shell script?

A shell script is an imperative list of commands that always runs in full. A Makefile is a declarative description of a dependency graph; Make decides what to run based on which files have changed. Make also parallelises naturally and stops on error by default.

What's the difference between GNU Make and BSD Make?

Same core idea, different syntax for anything beyond basic rules. .for loops, conditionals, variable modifiers all differ. GNU Make is what 99% of Linux/macOS Makefiles target. On BSD systems (and macOS), GNU Make is often called gmake.

Why the tab character for recipes?

Stuart Feldman wanted recipes to be visually distinct from target lines. He picked tab. By the time he realised it was a mistake, too many Makefiles existed to change it. Use .RECIPEPREFIX := > in GNU Make 3.82+ if you want a different character — but most projects stick with tab for consistency.

What order do rules execute in?

The order is dictated by the graph, not file position. Make walks from the goal, depth-first. Independent branches may parallelise with -j. The first target in the file is just the default goal (unless overridden with .DEFAULT_GOAL), not "the first thing to run".

What's the default goal?

The target Make builds when you type make with no arguments. By default: the first real (non-special) target defined in the Makefile. Set explicitly with .DEFAULT_GOAL := name.

What files does Make look for?

In order: GNUmakefile, makefile, Makefile. Use -f FILE to pick a specific one.

Syntax & semantics

What's the difference between = and :=?

= is recursively expanded: the right side is stored as text and re-evaluated every reference. := is simply expanded: the right side is evaluated once, at assignment, and the result is stored. Default to := unless you specifically need late binding.

What are all the variable assignment operators?

= recursive, := simple, ::= POSIX-simple (same as :=), ?= if-not-set, += append preserving flavor, != assign from shell output.

What do $@, $<, $^, $?, $*, $+, $| mean?

Target, first prerequisite, all prerequisites (deduped), prerequisites newer than target, stem of a pattern match, all prerequisites (with duplicates), order-only prerequisites.

What's a pattern rule?

A rule using % as a single wildcard. %.o: %.c applies to any .o → .c pair. The matched text (the stem) is available as $*.

What's a static pattern rule?

targets: target-pat: prereq-pat. Restricts a pattern to a specific target list. Example: $(OBJ): %.o: %.c applies only to files in OBJ.

What's the difference between include, -include, and sinclude?

include errors if file missing. -include (or sinclude) silently skips missing files. Use the latter for optional fragments like auto-generated .d files.

What's the difference between $(X) and $${X} in a recipe?

$(X) is a Make variable expanded by Make before the recipe is handed to the shell. $${X} (equivalently $$X) is a shell variable — Make expands $$ to $ and the shell then expands $X.

What does the @ at the start of a recipe line do?

Suppresses the usual "echo this command before running it". The command still runs.

What does a - at the start of a recipe line do?

Ignore non-zero exit status; don't stop the build if this command fails.

What does a + at the start of a recipe line do?

Run the command even under -n / -q / -t. Used for recursive $(MAKE) calls so the jobserver still works under dry run.

Phony, special, and wildcards

What does .PHONY do?

Tells Make that a target isn't a real file. Make won't check for a file with that name, always runs the recipe, and skips implicit rule matching. Mark all action targets (all, clean, test, install) as phony.

What's an order-only prerequisite?

A prerequisite whose existence is required, but whose mtime doesn't trigger rebuilds. Syntax: target: deps | order-only-deps. Canonical use: build directories.

What's the difference between .INTERMEDIATE, .SECONDARY, and .PRECIOUS?

.INTERMEDIATE: Make creates and then deletes these files when done. .SECONDARY: same treatment but don't delete. .PRECIOUS: don't delete on interrupt (Ctrl-C).

What does .DELETE_ON_ERROR do?

If a recipe fails, Make deletes the target it was trying to build. Prevents half-written files from looking "up to date" on the next run. Include in every non-trivial Makefile.

What's the difference between a double-colon rule and a grouped target?

Double-colon (::) rules: multiple independent rules for the same target, each fires when its own prerequisites change. Grouped target (&:): one recipe produces multiple files simultaneously; fires once even if multiple of the files are stale.

How do you make a target always run?

Declare it phony (.PHONY: target) and optionally make it depend on a FORCE phony target. Avoid if possible — always-rebuild targets defeat Make's purpose.

What's the difference between $(wildcard *.c) and *.c?

*.c is a literal string in variable assignments. $(wildcard *.c) expands to a space-separated list of matching files. In recipe contexts, the shell expands globs naturally.

How do I ensure a directory exists before writing to it?

Make it an order-only prerequisite: build/%.o: src/%.c | build, with a build: rule that does mkdir -p $@. Alternative: mkdir -p $(@D) in the recipe.

Flags & invocation

How do I override a variable from the command line?

make VAR=value target. Command-line assignments win over Makefile assignments (unless override is used) and over the environment.

How do I pass an environment variable into Make's recipes?

Export at the shell before calling Make (VAR=value make), or in the Makefile use export VAR to export a Make variable to child shells. .EXPORT_ALL_VARIABLES: exports everything.

What does -j do?

Run multiple recipes in parallel. -j N = up to N; -j alone = unlimited (rarely what you want). On modern machines, -j $(nproc) or -j 8 is a sane default.

What's the jobserver?

GNU Make's mechanism for letting recursive $(MAKE) calls share a single pool of parallel-job tokens. Prevents make -j 8 + recursive submakes from fork-bombing your machine.

What does -n do?

Dry run — print the recipes Make would execute, without running them. Essential for reviewing a build before committing to it.

What does -B do?

Unconditionally rebuild everything, ignoring timestamps. Useful when you know the dependency graph is wrong or just want a clean re-verify without make clean.

What does -k do?

Keep going after errors. Normally Make stops at the first failed recipe; with -k, it builds as much of the rest of the graph as it can before exiting non-zero. Handy in CI.

What does -W file (--what-if) do?

Pretend file was just modified. Combined with -n, answers: "what would change if I edited this file?"

Practical patterns

How do I do automatic header-dependency tracking in C/C++?

Add -MMD -MP to CFLAGS and include the generated .d files:

CFLAGS += -MMD -MP
OBJ := ... ; DEP := $(OBJ:.o=.d)
-include $(DEP)

Each compile emits a .d file with header deps; Make reads them on subsequent invocations.

How do I get a quiet build by default but verbose with V=1?
Q := $(if $(V),,@)
hello: hello.c
	$(Q)$(CC) $(CFLAGS) $< -o $@
How do I embed a git commit SHA in my binary?
VERSION != git describe --always --dirty 2>/dev/null || echo dev
CPPFLAGS += -DVERSION='"$(VERSION)"'

Then use VERSION as a C macro in your code.

How do I conditionally build for debug vs release?

Cleanest: use a computed variable name (Chapter 8):

CFLAGS_release := -O2 -DNDEBUG
CFLAGS_debug   := -O0 -g
BUILD ?= release
CFLAGS := $(CFLAGS_$(BUILD))

Invoke as make BUILD=debug.

How do I make a target-specific flag override?

debug: CFLAGS := -O0 -g — this flags only apply while building debug and its prerequisites.

How do I stop Make from deleting intermediate files?

.SECONDARY: with no arguments preserves all intermediates. Or list specific ones: .SECONDARY: foo.a foo.b.

How do I run something only when a file changes?

Declare the file as a prerequisite. Make will only fire the recipe when its mtime moves. For "only if git HEAD changed" and similar, you need a stamp file:

.git-hash: FORCE
	@SHA=$$(git rev-parse HEAD); \
	 [ -f $@ ] && [ "$$SHA" = "$$(cat $@)" ] || echo $$SHA > $@
FORCE:

build/version.h: .git-hash
	echo "#define GIT $$(cat .git-hash)" > $@
How do I fail fast if a required tool is missing?
$(if $(shell command -v ninja 2>/dev/null),,$(error 'ninja' not in PATH))

Quirks & gotchas

My Makefile says "missing separator". What's wrong?

Spaces where a tab should be. Recipe lines must start with a literal tab character. Turn on "show whitespace" in your editor and check.

Make keeps rebuilding X even though nothing changed. Why?

Likely causes, in order: (1) X depends on a phony target, so it rebuilds every time. (2) X's recipe doesn't actually produce the file it claims to. (3) A prereq is always newer (perhaps auto-generated or constantly touched by another process). Diagnose with make --debug=basic.

Make won't rebuild X even though I changed a header. Why?

Make doesn't know about the dependency. Either declare it explicitly (X.o: X.c header.h) or set up -MMD -MP auto-deps. Verify with make -p | grep X.o.

Why does my multi-line recipe lose its shell state between lines?

Each recipe line runs in its own shell by default. Chain with && or \, or set .ONESHELL: globally.

Why is my $SHELL_VAR empty in the recipe?

Because Make expanded $S (a Make variable, empty) and left HELL_VAR. Double the dollar: $$SHELL_VAR.

Why did Make run my target when the file already exists?

The target is declared .PHONY. Or: a prerequisite has a later mtime. Or: -B is in effect (check $(MAKEFLAGS)). Or: the target is chained via a pattern rule whose input is an intermediate that Make considers stale.

Why is make -j 4 slower than make -j 1?

Rare but real. Possibilities: (a) parallel link steps thrash disk/IO on hardware that parallelises poorly; (b) a race-dependent recipe is hitting locks; (c) the dependency graph is fully serial and -j adds overhead without parallelism. Usually (a) or (b) — profile with --output-sync=target.

How do I make Make forget one variable?

undefine VAR (GNU Make 3.82+). Note: for variables that came from the environment, also unexport.

Should I use Make or something newer?

Use Make when: you need a build tool that's already installed, the project is small-to-medium (under 10k files), a single Makefile can describe the graph, you want no configuration step. Use something newer (ninja + cmake, bazel, nix) when: you have cross-platform builds, you need hermetic reproducibility, you have 100k+ files, or you need content-based cache invalidation. Knowing Make well makes everything else easier to learn.

Bonus questions

What's MAKECMDGOALS?

A variable containing the list of goals the user passed on the command line. Useful for conditional logic like "skip dep generation when user ran make clean":

ifeq ($(filter clean,$(MAKECMDGOALS)),)
-include $(DEP)
endif
What's CURDIR?

The absolute path of Make's current working directory. Changes as Make enters subdirectories with -C.

What's MAKEFILE_LIST?

A variable that grows to contain every Makefile Make has read. Useful for $(lastword $(MAKEFILE_LIST)) — "the file that just got included".

How do I source a shell .env file?

Make doesn't natively read dotenv. Use either:

# Option 1: shell out and parse
include .env
# .env would look like:  FOO = bar   (plain Make syntax)

# Option 2: eval with export
include .env
export $(shell sed 's/=.*//' .env)
How do Make variables compare to shell variables?

Make variables exist in Make's memory and are expanded by Make before the recipe runs. Shell variables exist in the recipe's subshell(s). They occupy different namespaces. $(FOO) → Make; $$FOO → shell.

What does .LIBPATTERNS do?

Controls how Make resolves -lNAME prerequisites. Default: lib%.so lib%.a. If you list -lfoo as a prerequisite, Make looks for libfoo.so or libfoo.a in the library search path.

Why does ifeq "$(A)" "$(B)" fail weirdly?

The quoted form requires matching quote styles on both sides. ifeq "$(A)" "$(B)" works; ifeq ($(A),"$(B)") doesn't. Pick one style (the paren form is more common).

Does Make re-read the Makefile after include?

No — include is processed in-line during the initial parse. However, Make will restart if a Makefile (or included file) is a target that got rebuilt. That's how auto-dependency chains self-heal.

How do I write a Makefile that works on both GNU Make 3.81 and 4.x?

Avoid features new to 4.x: !=, $(file ...), &: grouped targets, .ONESHELL's error-propagation (was subtly different). Use $(shell …) + := instead of !=. Stay simple.

What's the one-line "most important thing to remember"?

Make executes a graph, not a script. Every other confusion (why things rebuild, why they don't, why ordering matters for some things and not others) flows from either remembering or forgetting this.
