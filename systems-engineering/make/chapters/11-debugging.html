Chapter 11 Debugging Make

When a Makefile misbehaves, you need tools. This chapter is every technique I use — -n, -p, --debug, --trace, $(info), the Make "database dump", and remake, a drop-in GNU Make fork with a real debugger.

-n — dry run

make -n (or --just-print) prints every recipe line it would run, without executing anything. This is the first tool to reach for. 

$ make -n
cc -O2 -c src/main.c -o build/main.o
cc -O2 -c src/greet.c -o build/greet.o
cc    build/main.o build/greet.o -o build/hello

When combined with -W file (--what-if), it answers "what would happen if I modified file":

$ make -n -W include/greet.h
cc -O2 -c src/main.c -o build/main.o
cc -O2 -c src/greet.c -o build/greet.o
cc    build/main.o build/greet.o -o build/hello

Without touching anything, you've learned that touching greet.h triggers both compile units and a relink.

-p — Make's internal database

make -p dumps everything Make knows: variables, rules, implicit rules, directories, targets, timestamps. It's verbose — ~6000 lines for a plain-vanilla invocation. Page through it: 

$ make -p -f /dev/null 2>/dev/null | less
$ make -p                              # for your Makefile specifically

Useful -p greps:

# All variables ending with _DEPS
$ make -p 2>/dev/null | grep '_DEPS ='

# The origin and value of CFLAGS
$ make -p 2>/dev/null | grep -A1 'CFLAGS'

# Every built-in pattern rule
$ make -p -f /dev/null 2>/dev/null | grep '^%'

Add -n to -p for "dry run + dump" — a safe post-mortem if make itself succeeds but behaves oddly.

--debug

Several flavors:

FlagShows
--debug=basic or -dDecisions Make made: "target X needs rebuild because Y is newer"
--debug=verbose Basic + searched implicit rules, skipped prereqs
--debug=implicit Just implicit rule searches
--debug=jobs Process scheduling, parallelism, exit codes
--debug=makefile Re-reading of included makefiles
--debug=all or -d Everything
--debug=none Disable (from MAKEFLAGS, etc.)

Combine: --debug=basic,jobs. Most useful starter: --debug=basic.

$ make --debug=basic hello
GNU Make 4.4.1
...
Reading makefiles...
Updating goal targets....
File 'hello' does not exist.
 File 'main.o' does not exist.
  Must remake target 'main.o'.
cc -O2 -c main.c -o main.o
...

If Make refuses to rebuild something you expected it to rebuild, --debug=basic usually tells you why in one line.

--trace

GNU Make 4.0+. Prefixes each executed recipe line with the rule it came from and the reason it's running: 

$ make --trace
Makefile:12: update target 'build/main.o' due to: src/main.c
cc -O2 -c src/main.c -o build/main.o
Makefile:8: update target 'build/hello' due to: build/main.o
cc build/main.o -o build/hello

--trace is often more actionable than --debug=basic because it maps each command back to a specific Makefile line.

Printf debugging: $(info), $(warning), $(error)

These we met in Chapter 6. Used for inspecting values at parse time.

$(info CC       = $(CC))
$(info CFLAGS   = $(CFLAGS))
$(info SRC      = $(SRC))
$(info OBJ      = $(OBJ))
$(info MAKECMDGOALS = $(MAKECMDGOALS))
$(info MAKEFILE_LIST = $(MAKEFILE_LIST))

Put these at the top of a misbehaving Makefile and re-run. 80% of "why is this variable empty?" bugs die immediately.

The $(error) variant halts immediately. Useful for guards:

ifndef PROD_HOST
$(error PROD_HOST must be set for 'deploy')
endif

The "print-VAR" idiom

A tiny pattern rule every Makefile should have:

print-%:
	@echo '$* = $($*)'
	@echo '  origin = $(origin $*)'
	@echo '  flavor = $(flavor $*)'
	@echo '  value  = $(value $*)'

Now:

$ make print-CFLAGS
CFLAGS = -O2 -Wall -MMD -MP
  origin = file
  flavor = simple
  value  = -O2 -Wall -MMD -MP

$ make print-SRC
SRC = src/main.c src/greet.c
  origin = file
  flavor = simple
  value  = $(wildcard src/*.c)

The value line shows the unexpanded template — often more diagnostic than the expanded value.

Common errors and what they mean

ErrorMeaning
*** missing separator. Stop. A recipe line without a leading tab. Or a continuation of a non-recipe line that Make can't make sense of.
*** No rule to make target 'X', needed by 'Y'. Stop. A prereq X doesn't exist and no rule explains how to build it. Typo, missing file, wrong path.
make: Nothing to be done for 'X'. The target exists and is up to date — OR it's a phony target accidentally shadowed by a real file. Check .PHONY.
*** Recursive variable 'X' references itself (eventually). Stop. You wrote X = $(X) foo. Switch to := or +=.
*** recipe commences before first target. Stop. A tab-indented line appeared before Make saw a rule. Often caused by stray indentation inside a conditional, or misplaced endef.
commands commence before first target. Old-spelling of the above. Same bug.
*** target pattern contains no '%'. Bad static pattern rule syntax. The middle argument must contain %.
warning: overriding recipe for target 'X' Two non-:: rules define a recipe for the same target. Usually a duplicate you forgot about.
warning: undefined variable 'X' Only with --warn-undefined-variables. Typo in a variable name. Fix it.

Always run with --warn-undefined-variables

Put this near the top of your Makefile (or set it in MAKEFLAGS): 

MAKEFLAGS += --warn-undefined-variables

Catches typos instantly. $(CFLGS) instead of $(CFLAGS) would silently expand to empty — with this flag, Make warns, and you save yourself an afternoon.

remake — a Make with a debugger

remake is a fork of GNU Make that adds a proper interactive debugger. It installs alongside Make. 

$ brew install remake        # macOS
$ apt install remake          # Debian/Ubuntu
$ remake -X                   # enter debugger at start

remake> target hello
remake> step
remake> show variable CFLAGS
remake> where
remake> quit

Treat it as gdb for Make. When $(info) isn't enough and you need to trace through expansion live, remake is worth the install. It also gives you nicer error messages (source line and column for missing separator).

Build transcripts

Sometimes you want every executed command, readably:

$ make -j 1 --output-sync=target | tee build.log 2>&1

Forcing -j 1 preserves sequential order so the log is coherent. Redirect and grep later.

Inspecting timestamps

When "Make isn't rebuilding X", check the timestamps:

$ stat -f "%m %N" build/*.o  include/*.h   # macOS / BSD
$ stat -c "%Y %n" build/*.o  include/*.h   # Linux

You're looking for an .o that's older than a .h it should depend on. If the .o is newer, Make considers it up-to-date — correctly, per its rules. Bug is in your dependencies.

Which Makefiles did Make actually read?

$(info Makefile list: $(MAKEFILE_LIST))

MAKEFILE_LIST grows as Make reads files via include. If you expected an include to fire and it didn't, this tells you.

Hands-on: debug a broken build

Hands-on · three-bug scavenger hunt

Here's a Makefile with three bugs. See how fast you can find them.

makebroken.mk
CC     = cc
CFLGS  = -O2 -Wall
SRC    = $(wildcard src/*.c)
OBJ    = $(SRC:.c=.o)

.PHONY: all clean
all : hello

hello: $(OBJ)
    $(CC) $(CFLAGS) $^ -o $@

%.o: %.c
	$(CC) $(CFLGS) -c $< -o $@

clean:
	rm -f hello *.o

Try to build. What goes wrong?

Show solution — three bugs
  1. Bug 1: tabs vs spaces. The $(CC) $(CFLAGS) $^ -o $@ line under hello: begins with spaces, not a tab. Error: *** missing separator. Fix by retyping the indent with a real tab.
  2. Bug 2: typo in variable name. The recipes use $(CFLAGS) (which is never set), but the variable is defined as CFLGS. The compile commands silently use an empty string. Running with MAKEFLAGS += --warn-undefined-variables would catch this. Fix by renaming to CFLAGS.
  3. Bug 3: OBJ paths. SRC is src/main.c src/greet.c ...; the substitution $(SRC:.c=.o) gives src/main.o src/greet.o ..., but the pattern rule %.o: %.c will produce top-level main.o greet.o ... because that's where Make will write them unless the pattern specifies otherwise. Mismatch: Make can't find src/main.o because the rule makes main.o from main.c, not from src/main.c. Debug: make -n or make print-OBJ. Fix: write a path-aware rule: $(SRC:src/%.c=src/%.o) as your OBJ, and a matching pattern rule src/%.o: src/%.c. Or move OBJ to build/ as in Chapter 9.

EX 11.2 medium Explain this behavior

A user complains:

$ make
cc -c main.c -o main.o
$ make
cc -c main.c -o main.o          # it keeps rebuilding even though nothing changed

How do you diagnose what's going on?

Show solution

Run make --debug=basic:

$ make --debug=basic
 File 'main.o' does not exist.

Interesting — Make thinks main.o doesn't exist, but we clearly just built it. Possibilities:

  • The recipe doesn't actually write main.o (typo in target name? outputs to a different path?).
  • Something (a clean script in a hook, a CI artifact cleaner) is deleting it.
  • Make is looking in the wrong directory (vpath, VPATH confusion).

ls -la main.o after the build confirms whether the file actually exists. If it does but Make doesn't see it, check make -p 2>/dev/null | grep main.o for what path Make expects.

EX 11.3 medium Why didn't it rebuild?

A colleague edited util.h and expected util.o to rebuild, but it didn't. Walk through the steps you'd take to diagnose.

Show solution
  1. make -W include/util.h -n — what would rebuild if that file were newer? If nothing, the dependency is missing.
  2. make -p | grep util.o — what prereqs does Make think util.o has? If only util.c, the header dep isn't known.
  3. Check if the project uses -MMD -MP. If yes, look for build/util.d — does it list util.h?
  4. Is the -include $(DEP) line present and is $(DEP) non-empty? (make print-DEP)

Most likely cause: a stale dep file, or -include was accidentally removed, or the dep file wasn't produced (missing -MMD in CFLAGS).

EX 11.4 medium Parse-time vs build-time info

You want to print "Starting build…" at the start of the build (after rules are known, before recipes run), and "Done." at the end. How?

Show solution

A top-level $(info) fires at parse time — which is essentially "start of build". For "end of build", add a phony target that depends on the real goal: 

$(info Starting build...)

.PHONY: all done
all: done

done: $(BIN)
	@echo "Done."

# … real targets …

Or use a "last goal" hook via a canned recipe. Make doesn't have a built-in "finalizer", so the cleanest way is to make the real goal a prereq of a thin wrapper.

EX 11.5 hard Trace a rebuild decision

Using --trace, determine the exact reason Make rebuilds a target of your choice. Copy the line it prints and explain it.

Show solution

Example output from running make --trace after touch src/greet.c:

Makefile:23: update target 'build/greet.o' due to: src/greet.c
cc -O2 -MMD -MP -c src/greet.c -o build/greet.o
Makefile:18: update target 'build/hello' due to: build/greet.o
cc build/main.o build/greet.o -o build/hello

Reads: "at Makefile line 23, update target build/greet.o because the prerequisite src/greet.c is newer". Then line 18 triggers for the same reason one level up. This is how Make decisions become legible.

EX 11.6 hard Build a check-target

Write a Makefile fragment that, before anything else, verifies the required tools (cc, pkg-config, python3) exist on PATH. Error clearly if any is missing.

Show solution 
REQUIRED := cc pkg-config python3

define check_tool
$(if $(shell command -v $(1) 2>/dev/null),, \
    $(error Required tool '$(1)' not found in PATH))
endef

$(foreach t,$(REQUIRED),$(call check_tool,$(t)))

Fires at parse time — before any recipe runs. Clean failure mode.

Recap

  • make -n — dry run, shows what would run.
  • make -W file -n — "what if this file changed".
  • make -p — dump Make's internal database.
  • make --debug=basic / --trace — why each target is rebuilding.
  • $(info) $(warning) $(error) — printf debugging at parse time.
  • The print-% pattern rule — inspect any variable on demand.
  • MAKEFLAGS += --warn-undefined-variables — catches typos.
  • remake — Make with a real debugger.
  • Check timestamps with stat when "why isn't this rebuilding?" is the question.
