Chapter 14 Capstone — the broken pipeline

You've inherited a small C++ program. It is supposed to read records from a Unix socket, count them by type in a worker pool, and write a summary to a file every second. It does — sometimes. Other times it crashes, hangs, leaks, or prints garbage. Your job: find every bug. Use everything from the previous thirteen chapters.

How to work this capstone. Read the source once. Build it. Run it. Watch it misbehave. Form a hypothesis. Pick the right tool from your toolbox. Verify. Fix. Repeat. Don't read the “debrief” section until you've found at least four of the bugs yourself.

The program

Save the following as aggregator.cpp. It compiles with C++20. The bugs are intentional; do not “clean it up” before debugging — that defeats the exercise.

cppaggregator.cpp
// Capstone: deliberately broken. Find the bugs.
// Build:  c++ -std=c++20 -O2 -g -pthread aggregator.cpp -o aggregator
// Run:    ./aggregator /tmp/agg.sock /tmp/summary.txt

#include <atomic>
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <condition_variable>
#include <mutex>
#include <queue>
#include <string>
#include <thread>
#include <vector>
#include <unistd.h>
#include <signal.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <fcntl.h>

struct Record {
    char type;     // 'A'..'Z'
    int  payload;
};

static std::queue<Record*> q;
static std::mutex          q_mu;
static std::condition_variable q_cv;
static std::atomic<bool>   stopping{false};

static int counts[26];   // shared, no lock

static volatile sig_atomic_t got_sigint = 0;

static void on_sigint(int) {
    got_sigint = 1;
    fprintf(stderr, "\ncaught SIGINT, shutting down...\n");
    stopping = true;
    q_cv.notify_all();
}

static void worker() {
    while (!stopping) {
        std::unique_lock lk(q_mu);
        if (q.empty()) q_cv.wait(lk);
        Record* r = q.front();
        q.pop();
        lk.unlock();

        if (r->type >= 'A' && r->type <= 'Z')
            counts[r->type - 'A']++;
        // forgot to free r
    }
}

static void writer(const char* path) {
    while (!stopping) {
        sleep(1);
        FILE* f = fopen(path, "w");
        if (!f) continue;
        for (int i = 0; i < 26; i++)
            fprintf(f, "%c=%d\n", 'A'+i, counts[i]);
        fclose(f);
    }
}

static int make_listener(const char* path) {
    int fd = socket(AF_UNIX, SOCK_STREAM, 0);
    sockaddr_un a{};
    a.sun_family = AF_UNIX;
    strcpy(a.sun_path, path);
    unlink(path);
    bind(fd, (sockaddr*)&a, sizeof a);
    listen(fd, 8);
    return fd;
}

int main(int argc, char** argv) {
    if (argc < 3) { fprintf(stderr, "usage: %s SOCK OUT\n", argv[0]); return 2; }
    signal(SIGINT, on_sigint);

    int lfd = make_listener(argv[1]);

    std::vector<std::thread> pool;
    for (int i = 0; i < 4; i++) pool.emplace_back(worker);
    std::thread w(writer, argv[2]);

    char buf[64];
    while (!stopping) {
        int cfd = accept(lfd, nullptr, nullptr);
        if (cfd < 0) continue;
        ssize_t n = read(cfd, buf, sizeof buf);
        if (n > 0) {
            Record* r = new Record;
            r->type    = buf[0];
            r->payload = atoi(buf + 1);
            {
                std::lock_guard lk(q_mu);
                q.push(r);
            }
            q_cv.notify_one();
        }
        close(cfd);
    }

    for (auto& t : pool) t.join();
    w.join();
    close(lfd);
    return 0;
}

$ ./aggregator /tmp/agg.sock /tmp/summary.txt &

# In another terminal:
$ for i in $(seq 1 10000); do

  done

$ cat /tmp/summary.txt   # numbers should add up to 10000

What you'll see

  • Counts in summary.txt sometimes add up to less than the number of records sent.
  • RSS in top climbs steadily and never comes down.
  • Hitting Ctrl-C sometimes hangs the process for several seconds, sometimes crashes it.
  • Under TSan: data race reports on counts[] and on q.
  • Under ASan: direct leaks from the new Record path.
  • Occasional segfault inside the worker on shutdown.
  • If the same socket path already exists with the wrong permissions, the program silently ignores the bind error.

A guided debugging walk

This is one route to the bugs. Yours might differ; that's fine — the point is to develop reflexes.

Step 1 — first read

Before touching anything, read once with intent. Note things that look suspicious. From the source above:

  • counts[26] is plain int shared across threads. Race candidate.
  • q_cv.wait(lk) with no predicate. Spurious wakeup, missed signal.
  • worker() calls q.front() after a wakeup with no check that the queue is non-empty. UB on shutdown.
  • r is allocated with new and never freed. Leak.
  • strcpy into a.sun_path with no length check. Overflow if path > 108 bytes.
  • bind/listen return values not checked. Silent failure.
  • fprintf + q_cv.notify_all from a signal handler. Async-signal-unsafe.
  • The writer reads counts[] while workers write — another race.
  • The writer rewrites summary.txt with fopen("w") — not atomic, partial files visible.
  • accept blocks indefinitely; Ctrl-C can't unstick it — shutdown hang.

Step 2 — sanitizers do half the work

$ c++ -std=c++20 -O1 -g -pthread \
    -fsanitize=address,undefined \
    -fno-omit-frame-pointer \
    aggregator.cpp -o aggregator-asan

$ c++ -std=c++20 -O1 -g -pthread \
    -fsanitize=thread \
    -fno-omit-frame-pointer \
    aggregator.cpp -o aggregator-tsan

Run each variant against the load generator. ASan will print direct leak stacks pointing at new Record. TSan will report races on counts[i] and on the queue's internal state if you ever managed to bypass the mutex. The first fix is mechanical:

  • Wrap each counts[] entry in std::atomic<int>, or hold a separate mutex when reading/writing it. Atomics are simpler.
  • Use std::unique_ptr<Record> in the queue; the worker drops the unique_ptr at scope end and the leak is gone.

Step 3 — fix the condition variable

The current pattern is the textbook bug:

// BAD
if (q.empty()) q_cv.wait(lk);
Record* r = q.front();
q.pop();

If the wakeup is spurious, or if it came from the shutdown path with an empty queue, q.front() is UB. Replace with the predicate loop:

// GOOD
q_cv.wait(lk, []{ return !q.empty() || stopping; });
if (q.empty()) return;          // shutdown
auto r = std::move(q.front());
q.pop();

Step 4 — signal handler hygiene

The handler calls fprintf and q_cv.notify_all. Both can deadlock or corrupt state if the signal lands while another thread holds the relevant lock. Two fixes, pick one:

  1. Bare-minimum handler. Only set got_sigint = 1 and a self-pipe / eventfd. Have main call write(self_pipe[1], "x", 1) in the handler (write is async-signal-safe). The accept loop selects on listener + self-pipe and exits cleanly.
  2. signalfd. Block SIGINT in all threads with pthread_sigmask, register a signalfd in main, treat the signal as an ordinary readable event in the same poll loop as accept.

Either way, the signal handler stops being a correctness hazard and shutdown stops hanging on a blocked accept.

Step 5 — safe socket setup

// BAD
strcpy(a.sun_path, path);
bind(fd, (sockaddr*)&a, sizeof a);
listen(fd, 8);

// GOOD
if (strlen(path) >= sizeof a.sun_path) {
    fprintf(stderr, "socket path too long\n");
    return -1;
}
strncpy(a.sun_path, path, sizeof a.sun_path - 1);
unlink(path);
if (bind(fd, (sockaddr*)&a, sizeof a) < 0) { perror("bind"); return -1; }
if (listen(fd, 8) < 0)                      { perror("listen"); return -1; }

Step 6 — atomic file replacement

// In writer():
char tmp[256];
snprintf(tmp, sizeof tmp, "%s.tmp.%d", path, getpid());
int fd = open(tmp, O_WRONLY | O_CREAT | O_TRUNC, 0644);
// ... write counts to fd ...
fsync(fd);
close(fd);
rename(tmp, path);
// fsync the directory too if you care about crash safety

Step 7 — frame-by-frame in GDB

If after all that you still get an occasional segfault, run under GDB and let it catch the SIGSEGV:

$ gdb --args ./aggregator /tmp/agg.sock /tmp/summary.txt
(gdb) handle SIGINT pass nostop noprint
(gdb) catch syscall
(gdb) run
# reproduce, then on crash:
(gdb) thread apply all bt
(gdb) frame 2
(gdb) info args
(gdb) info locals

The most useful single trick: once you suspect a particular address is being smashed, set a hardware watchpoint on it and restart. The writer becomes obvious.

A reference fixed version

Don't read this until you've debugged on your own. The fix is not unique — this is one acceptable shape.

cppaggregator-fixed.cpp (excerpt)
#include <array>
#include <atomic>
#include <memory>
#include <sys/eventfd.h>
#include <sys/epoll.h>
#include <sys/signalfd.h>

static std::queue<std::unique_ptr<Record>> q;
static std::mutex          q_mu;
static std::condition_variable q_cv;
static std::atomic<bool>   stopping{false};
static std::array<std::atomic<int>, 26> counts{};

static void worker() {
    for (;;) {
        std::unique_lock lk(q_mu);
        q_cv.wait(lk, []{ return !q.empty() || stopping; });
        if (q.empty()) return;
        auto r = std::move(q.front());
        q.pop();
        lk.unlock();

        if (r->type >= 'A' && r->type <= 'Z')
            counts[r->type - 'A'].fetch_add(1, std::memory_order_relaxed);
    }
}

static void writer_atomic(const char* path) {
    while (!stopping) {
        sleep(1);
        char tmp[256];
        snprintf(tmp, sizeof tmp, "%s.tmp.%d", path, getpid());
        int fd = open(tmp, O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd < 0) continue;
        for (int i = 0; i < 26; i++) {
            char line[32];
            int n = snprintf(line, sizeof line, "%c=%d\n",
                             'A'+i,
                             counts[i].load(std::memory_order_relaxed));
            write(fd, line, n);
        }
        fsync(fd);
        close(fd);
        rename(tmp, path);
    }
}

int main(int argc, char** argv) {
    if (argc < 3) { fprintf(stderr, "usage: %s SOCK OUT\n", argv[0]); return 2; }

    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGTERM);
    pthread_sigmask(SIG_BLOCK, &mask, nullptr);

    int sfd = signalfd(-1, &mask, SFD_CLOEXEC);
    int lfd = make_listener(argv[1]);
    if (lfd < 0) return 1;

    std::vector<std::thread> pool;
    for (int i = 0; i < 4; i++) pool.emplace_back(worker);
    std::thread w(writer_atomic, argv[2]);

    int ep = epoll_create1(EPOLL_CLOEXEC);
    epoll_event ev{};
    ev.events = EPOLLIN; ev.data.fd = lfd; epoll_ctl(ep, EPOLL_CTL_ADD, lfd, &ev);
    ev.data.fd = sfd;                       epoll_ctl(ep, EPOLL_CTL_ADD, sfd, &ev);

    while (!stopping) {
        epoll_event out;
        if (epoll_wait(ep, &out, 1, -1) < 1) continue;
        if (out.data.fd == sfd) { stopping = true; q_cv.notify_all(); break; }
        int cfd = accept4(lfd, nullptr, nullptr, SOCK_CLOEXEC);
        if (cfd < 0) continue;
        char buf[64];
        ssize_t n = read(cfd, buf, sizeof buf);
        if (n > 0) {
            auto r = std::make_unique<Record>();
            r->type    = buf[0];
            r->payload = atoi(buf + 1);
            { std::lock_guard lk(q_mu); q.push(std::move(r)); }
            q_cv.notify_one();
        }
        close(cfd);
    }

    for (auto& t : pool) t.join();
    w.join();
    close(lfd); close(sfd); close(ep);
    return 0;
}

Exercises

14.1 medium Add a regression test

Write a shell script that drives the aggregator with a known input distribution (say, 100 records each of 'A'..'Z'), waits for the writer cycle, and asserts that summary.txt shows exactly 100 of each. Run it a thousand times in a loop. The flakiness rate before and after your fixes is your scoreboard.

Hint

Use nc -U -q0 to send and a sleep 2 plus a while ! diff <(expected) summary.txt; do sleep 0.1; done with a timeout. Wrap in for i in $(seq 1 1000); do ...; done and count failures. The atomic rename + atomic counters fix should bring failures to zero.

14.2 hard Convert to a single-thread epoll design

Replace the worker pool with a single thread that drives everything off epoll: the listener, accepted connections, a timerfd for the writer, and the signalfd for shutdown. No locks, no condvars, no atomics needed. Compare throughput via a load generator.

Hint

Each accepted connection becomes non-blocking and joins epoll edge-triggered. timerfd_create + 1-second interval drives the summary write. Counters are now plain ints in a struct because there's exactly one accessor. This design is what production servers like nginx use; it's typically faster than a small thread pool because there's no contention to begin with.

14.3 hard Make it survive a kill -9 mid-write

Kill the process with kill -9 at random times during the writer loop. Verify summary.txt is always either the previous fully-written summary or the latest one — never a half-written or missing file. Then power-cut the VM (or use echo b > /proc/sysrq-trigger) and verify durability.

Hint

The atomic-replace pattern: write to summary.txt.tmp, fsync the tmp, rename(tmp, summary.txt), then fsync the parent directory. The directory fsync is what most engineers forget; without it, the rename can be lost across a power cut even though the data file is on disk.

14.4 medium Wire it into CI under three sanitizer matrices

Build the program three ways: release (-O2), ASan+UBSan (-O1 -fsanitize=address,undefined), TSan+UBSan (-O1 -fsanitize=thread,undefined). Run the regression test from 14.1 against each. Assert sanitizer error count is zero.

Hint

ASan and TSan can't be combined — they instrument the allocator differently. Three jobs in CI is the standard. Set ASAN_OPTIONS=halt_on_error=1 detect_leaks=1 and TSAN_OPTIONS=halt_on_error=1 second_deadlock_stack=1. A single sanitizer report should fail the build.

Recap — what you should leave with

  • You can take a multi-threaded C++ program with race + UB + leak + signal-handler bug + I/O-durability bug and find every class of bug with the right tool.
  • You know which tool fits each bug class: TSan for races, ASan for memory errors, GDB watchpoints for “who corrupted this”, strace for hangs, code review for signal-handler hygiene and durability.
  • You have an idiom for shutdown that doesn't use signal-from-a-handler tricks: signalfd + epoll + a stopping atomic.
  • You have an idiom for atomic file updates: write tmp + fsync + rename + fsync dir.
  • You can articulate why the bugs are bugs, in the language of the C/C++ memory model and the Linux kernel.

That's the whole tutorial. Build something with this. Break it on purpose. Then break it by accident, and watch how much faster you find the cause now than before.
