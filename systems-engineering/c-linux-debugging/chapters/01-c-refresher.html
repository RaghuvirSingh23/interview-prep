Chapter 01 C — the working subset

C is small but treacherous. This chapter covers the parts you can trust, the parts you can't, and the rules behind both. Pointers, arrays, integer promotion, structs, declarators, and the idioms a systems programmer reaches for daily.

A "hello, world" worth re-reading

chello.c
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("hello, %s\n", argc > 1 ? argv[1] : "world");
    return 0;
}

$ cc -std=c17 -Wall -Wextra -Wpedantic -O2 -g hello.c -o hello
$ ./hello there
hello, there

Things that should be reflex from line one:

  • -std=c17 (or -std=c11 on older compilers, -std=c23 on bleeding-edge). Don't compile against the unstated implementation default.
  • -Wall -Wextra -Wpedantic always. Add -Wshadow -Wconversion -Wnull-dereference -Wstrict-prototypes to taste.
  • -O2 -g gives optimised code with debug symbols. -Og gives a debug-friendly build with most opts off.
  • -fsanitize=address,undefined is your friend during development. Chapter 11.

Types — what they really are

Integer types in C are sized by the implementation, with minimums:

TypeMin sizeCommon on 64-bit Linux
char 1 byte (≥8 bits)1 byte, signedness implementation-defined
short ≥16 bits 2 bytes
int ≥16 bits 4 bytes
long ≥32 bits 8 bytes (LP64)
long long ≥64 bits 8 bytes
size_t unsigned, big enough for any object size8 bytes
ptrdiff_t signed pointer difference8 bytes

For anything where width matters — file formats, wire protocols, cross-platform code — use the fixed-width types from <stdint.h>:

#include <stdint.h>
#include <inttypes.h>

uint32_t  u32;
int64_t   i64;
uintptr_t addr;        /* integer big enough for a pointer */

printf("%" PRIu32 " %" PRId64 "\n", u32, i64);

Use PRIu32/PRId64/PRIxPTR macros for printf — they give the right format string regardless of platform.

Signedness and integer promotion

The single most-foot-gunned area of C. Two rules, learned the hard way:

  1. Anything narrower than int is promoted to int in expressions. A uint8_t a = 0xff; uint8_t b = 0xff; then a * b is computed as int — no overflow, value 0xfe01.
  2. Mixing signed and unsigned converts the signed to unsigned if the unsigned type is at least as wide. -1 < 1u is false, because -1 becomes UINT_MAX.
int   x = -1;
unsigned y = 1;
if (x < y) puts("yes"); else puts("no");
/* prints "no" — x is converted to unsigned (huge), then compared. */

Practical defenses:

  • Compile with -Wsign-compare -Wsign-conversion. The warnings sting; fix them.
  • Prefer signed types for arithmetic where you don't need the high bit. Use unsigned for bit-fiddling.
  • Indices into arrays: size_t (unsigned), but be careful with downward loops.

Pointers — the four-line summary

int  x = 42;
int *p = &x;       /* p points at x */
int  y = *p;       /* dereference: y is now 42 */
*p = 7;            /* through p, store into x; now x == 7 */

Common rookie traps:

int *p;            /* p is uninitialised — points anywhere */
*p = 5;            /* UB: write to who-knows-where */

int *q = NULL;
*q = 5;            /* UB: NULL deref. Often a SIGSEGV — but NOT guaranteed. */

int *r;
{
    int local = 10;
    r = &local;
}
printf("%d\n", *r);  /* UB: r dangles, local has gone out of scope. */

Sanitizers catch all three; running unchecked code "on Tuesday" doesn't.

Arrays vs pointers — the iconic confusion

An array is not a pointer. But array names decay to pointers in most expression contexts.

int a[10];

sizeof(a)  == 40    /* (assuming int is 4) */
sizeof(&a) == 8     /* size of a pointer-to-array-of-10-ints, which is 8 on x86_64 */

int *p = a;         /* OK: a decays to int* in this context */
sizeof(p)  == 8     /* p is a pointer; sizeof gives pointer size */

void f(int x[10]) {
    sizeof(x);      /* this is sizeof(int*) — 8. The "[10]" was a polite lie. */
}

Three-line rule of thumb:

  1. Inside the scope where it was declared, an array remembers its size.
  2. Pass an array to a function: it becomes a pointer, the size is gone, you must pass the size separately.
  3. sizeof, &, and string literals as initialisers are the contexts where the array doesn't decay.

Declarators — read them spirally

C declarations read inside-out (and right-to-left for the modifiers). The classic exercises:

int  *p;            /* p is a pointer to int */
int  *p[10];        /* p is an array[10] of pointers to int */
int (*p)[10];       /* p is a pointer to an array[10] of int */
int (*f)(int);      /* f is a pointer to a function taking int and returning int */
int  *f(int);       /* f is a function taking int and returning a pointer to int */
int (*fp[10])(int); /* fp is an array[10] of pointers to function (int) -> int */

When in doubt, cdecl (or the website cdecl.org) translates to English. Memorise the spiral rule and you'll read function-pointer-heavy code without flinching.

Strings — null-terminated bytes, that's all

A C string is "an array of char terminated by a '\0' byte". The terminator is part of the contract. Forget it once and you have UB.

char  s[] = "hello";    /* 6 bytes: h e l l o \0 */
char *t   = "hello";    /* pointer to a (read-only!) string literal */
t[0] = 'H';             /* UB: writing to a string literal */

size_t n = strlen(s);   /* 5 — does not count the \0 */

Functions to know cold from <string.h>:

strlen length, not counting NUL
strcpy / strncpyboth treacherous; prefer snprintf or strlcpy
strcmp ≤0/0/≥0 like Unix sort
strchr / strrchrfind char
strstr find substring
memcpy raw bytes; non-overlapping; faster than strcpy
memmove raw bytes; allows overlap
memcmp raw bytes equality
memset fill region
strcpy is a footgun, strncpy is a different footgun

strcpy writes until it sees a NUL — buffer-overflow paradise. strncpy writes exactly n bytes, padding with NULs or truncating without NUL-terminating. Read that twice. Use snprintf(dst, sizeof dst, "%s", src) or BSD's strlcpy for sane copying.

Structs and aggregates

struct Point {
    int x;
    int y;
};

struct Point p = { .x = 1, .y = 2 };    /* designated initialiser */
struct Point q = p;                      /* member-wise copy */

p.x = 5;
struct Point *pp = &p;
pp->x = 5;                               /* same as (*pp).x = 5 */

Structs are passed by value. To avoid copies, pass const T *. Structs may have padding — never memcmp two structs to test equality unless you've zero-initialised them.

Anonymous unions and structs (C11) are useful for tagged unions and SoA-ish layouts. Bitfields are portable in spelling but their layout is implementation-defined — don't rely on them for wire formats.

Enums and tagged unions

typedef enum { OK, ERR_NOT_FOUND, ERR_BUSY, ERR_FATAL } Status;

typedef struct {
    enum { V_INT, V_STR } tag;
    union {
        int   i;
        char *s;
    };
} Value;

Value v = { .tag = V_INT, .i = 42 };
switch (v.tag) {
    case V_INT: printf("%d\n", v.i); break;
    case V_STR: printf("%s\n", v.s); break;
}

Enums in C are not strongly typed — they're ints in a trench coat. -Wswitch -Wswitch-enum gets you compile-time checks that every enumerator is handled.

Errors — the C convention

Most POSIX functions return 0/non-negative on success and -1 on failure, setting errno. Many libc functions return NULL on failure. Always check.

#include <errno.h>
#include <string.h>
#include <stdio.h>

FILE *f = fopen(path, "r");
if (!f) {
    fprintf(stderr, "fopen %s: %s\n", path, strerror(errno));
    return 1;
}

Use perror("fopen") or strerror(errno); never invent your own error string from the integer value (errno values aren't stable across systems for the textual descriptions).

Manual memory — malloc/free

#include <stdlib.h>

size_t n = 1000;
int *xs = malloc(n * sizeof *xs);   /* sizeof *xs, not sizeof(int) — survives type renames */
if (!xs) { perror("malloc"); return 1; }

memset(xs, 0, n * sizeof *xs);

xs = realloc(xs, 2*n * sizeof *xs); /* realloc may move; on failure returns NULL and old ptr survives */
if (!xs) { /* original is leaked here unless captured */ }

free(xs);
xs = NULL;                          /* defensive: prevents double-free smuggling in */

The four laws of malloc:

  1. Every malloc needs exactly one free.
  2. Don't free the same pointer twice.
  3. Don't use after free.
  4. Check for NULL on every allocation.

You won't follow them perfectly. That's why ASan exists.

Idioms worth memorising

/* Array length, only for true arrays (not pointers) */
#define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))

/* Compile-time assert */
_Static_assert(sizeof(int) == 4, "this code assumes 32-bit int");

/* Compound literal — anonymous struct */
foo(&(struct point){.x=1, .y=2});

/* Designated initialiser leaves unset members zero */
struct Config c = { .timeout_ms = 5000 };  /* every other field is 0 */

/* min/max as macros (no side effects in args, please) */
#define MIN(a,b) ((a) < (b) ? (a) : (b))
#define MAX(a,b) ((a) > (b) ? (a) : (b))

/* Container-of: from a pointer to a struct member, get a pointer to the struct.
   Linux kernel idiom; C11 has __typeof__. */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

Hands-on: a tiny program with -Wall, -fsanitize

Hands-on · catch a bug at compile time, then at run time
cbuggy.c
#include <stdio.h>
#include <string.h>

int main(void) {
    char buf[8];
    strcpy(buf, "hello, world");   /* writes 13 bytes into 8-byte buffer */
    printf("%s\n", buf);
    return 0;
}

$ cc -O2 -Wall buggy.c -o buggy
buggy.c:6:5: warning: 'strcpy' writing 13 bytes into a region of size 8 [-Wstringop-overflow=]

$ cc -O1 -g -fsanitize=address buggy.c -o buggy
$ ./buggy
=================================================================
==12345==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x... at pc 0x...
WRITE of size 13 at 0x... thread T0
    #0 0x...  in main buggy.c:6
...

Two layers of safety net. The compiler caught the obvious one; ASan would have caught it even if the source were obscured (e.g. strcpy(buf, runtime_string)).

Exercises

EX 1.1 easy Predict the output 
#include <stdio.h>
int main(void) {
    int   x = -1;
    unsigned y = 1;
    if (x < y) puts("less");
    else        puts("not less");

    char a = 0x80;
    int  b = a;
    printf("%d\n", b);
    return 0;
}
Show solution

"not less" — x is converted to unsigned (huge value).

-128 or 128 — depends on whether char is signed by default. On most x86_64 Linuxes, char is signed and you get -128. Compile with -funsigned-char and you get 128. Always specify signed char or unsigned char when the bit value matters.

EX 1.2 easy Read these declarations

Translate to English:

(a) char *(*p)[10];
(b) int (*signal(int, void (*)(int)))(int);
(c) const char * const *argv;
Show solution
  1. p is a pointer to an array of 10 pointers to char.
  2. Famous one: signal is a function taking an int and a pointer to a function (int)→void, returning a pointer to a function (int)→int. That's the actual POSIX signature for signal().
  3. argv is a pointer to a const pointer to a const char. You can't change what the pointers point to or the strings they point at — but you can change argv itself.
EX 1.3 medium strncpy without NUL

This compiles cleanly with -Wall. Find the bug.

void store(const char *src, char *dst) {
    strncpy(dst, src, 16);
    printf("stored: %s\n", dst);
}
Show solution

If strlen(src) >= 16, strncpy writes 16 bytes without a NUL terminator. The subsequent printf("%s", dst) reads past the buffer until it finds one — UB and information leak. Fix:

snprintf(dst, 16, "%s", src);    /* always NUL-terminates */

Or use strlcpy if available. Or use a real string type (C++ std::string, or your codebase's wrapper).

EX 1.4 medium Container-of in action

Given a list_node embedded in a struct, write a function that returns the enclosing struct from a list_node *.

Show solution 
#include <stddef.h>

struct list_node { struct list_node *next; };

struct task {
    int priority;
    struct list_node link;
    char name[32];
};

#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

struct task *task_from_node(struct list_node *n) {
    return container_of(n, struct task, link);
}

This is the cornerstone of intrusive data structures (Linux kernel uses it everywhere). The cast through char* is what makes pointer arithmetic in bytes well-defined.

EX 1.5 hard Find the leak / UB 
char *strdup_upper(const char *s) {
    size_t n = strlen(s);
    char *out = malloc(n);
    for (size_t i = 0; i < n; i++)
        out[i] = toupper((unsigned char)s[i]);
    return out;
}
Show solution
  1. Buffer too small: malloc(n) doesn't include the NUL terminator. Need n + 1.
  2. Not NUL-terminated: the caller can't safely use it as a C string.
  3. No NULL check: malloc can fail.
  4. Potential toupper UB: toupper takes an int with the value of an unsigned char or EOF. Passing a signed char can be UB if it's negative. The (unsigned char) cast is correct.
char *strdup_upper(const char *s) {
    size_t n = strlen(s);
    char *out = malloc(n + 1);
    if (!out) return NULL;
    for (size_t i = 0; i < n; i++)
        out[i] = toupper((unsigned char)s[i]);
    out[n] = '\0';
    return out;
}

Recap

  • Compile with -std=c17 -Wall -Wextra -Wpedantic -O2 -g and run dev with -fsanitize=address,undefined.
  • Use fixed-width types from <stdint.h> when bytes matter; size_t for indices and sizes.
  • Mind the unsigned-comparison trap and integer promotion to int.
  • Arrays decay to pointers in most contexts; sizeof, &, and string-literal initialisers are the exceptions.
  • Read declarations spirally; use cdecl when in doubt.
  • Strings are NUL-terminated byte arrays. strcpy/strncpy are footguns; prefer snprintf or strlcpy.
  • The four laws of malloc; the four laws are why sanitizers exist.
