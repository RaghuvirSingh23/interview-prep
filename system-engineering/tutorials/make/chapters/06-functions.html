Chapter 06 Functions

Make has a real function library — text manipulation, file-name munging, conditionals, iteration, even user-defined functions. Under the hood, Make is a text-processing language of surprising power. Here's every function you'll actually use.

Calling a function

The syntax is $(func arg1,arg2,...) — note: commas separate arguments, and leading spaces in arguments are stripped, but trailing spaces are preserved. That trips everyone up at least once.

$(subst foo,bar,hello foo world)          # hello bar world
$(patsubst %.c,%.o,main.c greet.c)         # main.o greet.o
$(filter %.c,main.c greet.h util.c)        # main.c util.c

Functions can nest, and values can be variables, and you can line-break with backslash-continuation:

CLEAN_SRC := $(patsubst %.c,%.o, \
                $(filter %.c, $(wildcard src/*)))

Text manipulation

FunctionDoes
$(subst FROM,TO,TEXT)Literal replace every FROM with TO.
$(patsubst PAT,REPL,TEXT)Pattern replace each word. % is the wildcard.
$(strip TEXT)Collapse whitespace: one space between words, none at the edges.
$(findstring NEEDLE,HAYSTACK)Returns NEEDLE if found, else empty.
$(filter PAT...,TEXT)Keep words matching any pattern.
$(filter-out PAT...,TEXT)Drop words matching any pattern.
$(sort TEXT)Alpha-sort and deduplicate.
$(word N,TEXT)The Nth word (1-indexed).
$(wordlist S,E,TEXT)Words S..E inclusive.
$(firstword TEXT)= $(word 1,...)
$(lastword TEXT)The last word.
$(words TEXT)Count of space-separated words.

Examples

$(subst e,E,Hello there)                   # HEllo thErE
$(patsubst %.c,%.o,main.c x.c y.h)         # main.o x.o y.h  — non-matching left alone
$(patsubst src/%,build/%,src/a src/b c)    # build/a build/b c
$(strip   hello     world  )               # hello world
$(filter    %.c %.h, a.c b.h c.o d.txt)    # a.c b.h
$(filter-out %.o,   a.c b.o c.c)           # a.c c.c
$(sort banana apple cherry apple)          # apple banana cherry  — deduped!
$(words one two three four)                # 4
$(word 2,one two three)                    # two
$(firstword a b c)                         # a
Substitution reference is patsubst in disguise

$(VAR:.c=.o) — the substitution reference you saw in Chapter 5 — is exactly $(patsubst %.c,%.o,$(VAR)). The colon form is terser for the common case. Use whichever reads better.

File-name munging

FunctionOn src/foo/bar.c
$(dir NAMES) src/foo/ (with trailing slash)
$(notdir NAMES) bar.c
$(suffix NAMES) .c
$(basename NAMES) src/foo/bar (strip extension)
$(addsuffix .o,NAMES)appends .o to each word
$(addprefix build/,NAMES)prepends build/ to each word
$(join A,B) element-wise concatenation of A and B words
$(wildcard PAT) shell-glob expansion — Chapter 5
$(realpath NAMES) canonical absolute paths (resolves symlinks)
$(abspath NAMES) absolute paths (without resolving symlinks)

Examples

SRC    := src/a.c src/b.c
$(dir $(SRC))              # src/ src/
$(notdir $(SRC))           # a.c b.c
$(basename $(SRC))         # src/a src/b
$(suffix $(SRC))           # .c .c
$(addsuffix .o,$(basename $(SRC)))       # src/a.o src/b.o
$(addprefix obj/,$(notdir $(SRC)))       # obj/a.c obj/b.c

You now have enough to express nearly any path transformation a build needs:

# Given: src/a.c src/b.c
# Want:  build/obj/a.o build/obj/b.o

SRC := $(wildcard src/*.c)
OBJ := $(patsubst src/%.c,build/obj/%.o,$(SRC))

Conditional functions

These are not conditional directives (which control which rules exist). They're functions that return different values based on predicates.

FunctionSemantics
$(if COND,THEN[,ELSE])If COND expands to non-empty, result is THEN, else ELSE.
$(or A,B,C)First non-empty of A, B, C.
$(and A,B,C)If any is empty, empty; else the last.
$(not X)Empty if X is non-empty. (GNU Make 4.4+)

Make has no "boolean" type; truthiness is "non-empty string".

VERBOSE ?=                         # empty unless user set V=1 or VERBOSE=1
Q := $(if $(VERBOSE),,@)           # @ if not verbose, nothing if verbose

hello: hello.c
	$(Q)$(CC) $(CFLAGS) $< -o $@

Now make runs quietly, but make VERBOSE=1 shows every command. This is the standard pattern for a "quiet build by default, loud when asked".

Iteration — $(foreach …)

$(foreach VAR,LIST,TEXT) evaluates TEXT once for each word in LIST, with VAR bound to the current word. Results are space-joined. 

OBJS := $(foreach src,$(wildcard *.c),$(src:.c=.o))
# equivalent to  $(wildcard *.c:.c=.o) ... which doesn't work, but
# also equivalent to  $(patsubst %.c,%.o,$(wildcard *.c)) which does.

Where foreach really shines is when you need more than a simple substitution:

LANGS := en fr de es
PAGES := index about contact

# Cross product: en/index.html en/about.html ... es/contact.html
OUTPUTS := $(foreach lang,$(LANGS), \
               $(foreach page,$(PAGES), \
                   $(lang)/$(page).html))

User-defined functions — $(call …)

Define a "function" as a variable whose body uses $(1), $(2), … for positional arguments. Invoke with $(call name,arg1,arg2,...). 

define greeting
Hello, $(1). It's $(2) today.
endef

all:
	@echo '$(call greeting,reader,Thursday)'
$ make
Hello, reader. It's Thursday today.

A more useful example — a helper that compiles into a specific output dir:

define compile
	$(CC) $(CFLAGS) -c $(1) -o $(2)
endef

build/%.o: src/%.c
	@mkdir -p $(@D)
	$(call compile,$<,$@)

In practice, you don't define many call-functions. For one-shot reuse, variables and pattern rules cover 90% of needs. Where call pays off is when you're generating many similar rules — covered in Chapter 8.

Metaprogramming — $(eval …)

$(eval …) evaluates its argument as Makefile syntax, at expansion time. This is how you generate rules programmatically. 

define make_greeting_rule
greet-$(1):
	@echo Hello, $(1)!
endef

$(eval $(call make_greeting_rule,world))
$(eval $(call make_greeting_rule,universe))

.PHONY: greet-world greet-universe
$ make greet-world
Hello, world!
$ make greet-universe
Hello, universe!

call expands the template with arguments, and eval feeds the result back into Make as if it were typed into the Makefile. This is staggeringly powerful. It's also how you dig your own grave when things go wrong, because debugging "eval"'d rules requires careful use of $(info …).

Running shell commands — $(shell …)

Invokes a shell command, substitutes its stdout:

GIT_SHA := $(shell git rev-parse --short HEAD 2>/dev/null)
HOSTNAME := $(shell hostname)
KERNEL   := $(shell uname -r)

Remember: $(shell …) runs every time the variable is referenced unless you store it with :=. In practice you always want := or != for shell results.

$(shell …) ignores the command's exit status. If you need to check it, use $(.SHELLSTATUS) — a special variable set after each $(shell …) call: 

SHA := $(shell git rev-parse HEAD)
ifneq ($(.SHELLSTATUS),0)
$(error git not available or not in a repo)
endif

Diagnostic functions

FunctionBehavior
$(info MSG) Prints MSG to stdout. Result: empty.
$(warning MSG)Prints filename:line: MSG to stderr. Result: empty.
$(error MSG) Prints filename:line: MSG and halts Make immediately.

These are your friends. They are the print-f debugging for Makefiles:

$(info SRC is $(SRC))
$(info OBJ is $(OBJ))
$(if $(filter clean,$(MAKECMDGOALS)),, \
    $(info Building in $(CURDIR)))

These are evaluated at parse time, not when rules fire. That's usually what you want when you're debugging variable values.

Metadata functions

$(origin VAR) where VAR came from (file, command line, …) — Chapter 4
$(flavor VAR) undefined, recursive, or simple
$(value VAR) unexpanded text of VAR (useful to print the template of a recursive var)
A = hello $(B)
B = world

$(info value of A is: $(value A))      # hello $(B)
$(info expanded A is: $(A))            # hello world

The $(file …) function — read/write files

Make can itself read and write files. Handy for writing response files for linkers with huge argument lists:

# Write OBJ names to a response file
$(file >build/objs.rsp,$(OBJ))

# Append
$(file >>build/log,extra line)

# Read (GNU Make 4.2+)
CONTENT := $(file <somefile.txt)

This bypasses shell's ARG_MAX limit on huge projects.

Hands-on: text munging drill

Hands-on · work the functions

Type this Makefile and predict the output before running:

makedrill.mk
SRC := src/a.c src/b.c src/c.cpp README.md

A := $(filter %.c,$(SRC))
B := $(filter-out %.md,$(SRC))
C := $(patsubst src/%,build/%,$(filter %.c,$(SRC)))
D := $(notdir $(A))
E := $(sort $(A) $(B))
F := $(words $(SRC))
G := $(word 2,$(SRC))
H := $(basename $(notdir $(A)))
I := $(addsuffix .o,$(H))

show:
	@echo "A: $(A)"
	@echo "B: $(B)"
	@echo "C: $(C)"
	@echo "D: $(D)"
	@echo "E: $(E)"
	@echo "F: $(F)"
	@echo "G: $(G)"
	@echo "H: $(H)"
	@echo "I: $(I)"

Now run make -f drill.mk show and compare:

$ make -f drill.mk show
A: src/a.c src/b.c
B: src/a.c src/b.c src/c.cpp
C: build/a.c build/b.c
D: a.c b.c
E: src/a.c src/b.c src/c.cpp
F: 4
G: src/b.c
H: a b
I: a.o b.o

Note: E lost README.md (not in either set) and deduplicated the overlap. G is 1-indexed. I demonstrates chaining: notdir→basename→addsuffix.

Exercises

EX 6.1 easy patsubst warmup

Given SRC := src/a.c src/b.c tools/helper.c, write an expression that produces build/src/a.o build/src/b.o build/tools/helper.o.

Show solution 
OBJ := $(patsubst %.c,build/%.o,$(SRC))

The % on the left side matches src/a, src/b, or tools/helper, and the same stem is inserted into build/%.o.

EX 6.2 easy Quiet by default

Write a Makefile where commands are silent unless you run it with V=1.

Show solution 
Q := $(if $(V),,@)

hello: hello.c
	$(Q)$(CC) $(CFLAGS) $< -o $@
	@echo "  LINK hello"

When V is empty, Q expands to @ and the compiler line is silenced; the @echo is always silent. With make V=1, Q is empty and the compiler line is echoed.

EX 6.3 medium Cross-product with foreach

Given ARCHES := x86_64 arm64 and CONFIGS := debug release, compute a list of build directories like build/x86_64-debug build/x86_64-release build/arm64-debug build/arm64-release.

Show solution 
ARCHES  := x86_64 arm64
CONFIGS := debug release

BUILD_DIRS := $(foreach a,$(ARCHES), \
                  $(foreach c,$(CONFIGS), \
                      build/$(a)-$(c)))

show: ; @echo $(BUILD_DIRS)
EX 6.4 medium Mini-template engine

Write a user-defined function make-test that takes a source file like test_foo.c and emits a two-line rule: a test_foo executable built from that source, and adds it to a list ALL_TESTS. Use $(eval).

Show solution 
define make-test
$(1:.c=): $(1)
	$$(CC) $$(CFLAGS) $$< -o $$@
ALL_TESTS += $(1:.c=)
endef

TESTS := $(wildcard test_*.c)
$(foreach t,$(TESTS),$(eval $(call make-test,$(t))))

.PHONY: check
check: $(ALL_TESTS)
	@for t in $^; do ./$$t || exit 1; done
	@echo "All tests passed."

Notice the $$ inside the template: we want the single $ to be inserted into the generated Makefile, so the eval sees $(CC), not a call-time expansion. Using $ when generating Makefile text is a recurring gotcha — when in doubt, double it.

EX 6.5 medium Shell status check

Write Make code that captures the output of git describe --dirty, but errors out clearly if git returns non-zero (e.g. not in a repo).

Show solution 
VERSION := $(shell git describe --dirty 2>/dev/null)
ifneq ($(.SHELLSTATUS),0)
$(error Could not run 'git describe'. Are you in a git repo?)
endif

all:
	@echo Building $(VERSION)

An alternative that degrades gracefully rather than errors:

VERSION := $(shell git describe --dirty 2>/dev/null || echo unknown)
EX 6.6 hard Assert non-empty

Define a user function require that errors out if a given variable is empty. Example: $(call require,PROD_HOST) should halt Make with "PROD_HOST is not set" if it's empty.

Show solution 
define require
$(if $(strip $($(1))),,$(error $(1) is not set))
endef

deploy:
	$(call require,PROD_HOST)
	scp release $(PROD_HOST):/opt/

Note: $($(1)) indirectly dereferences — if $(1) is PROD_HOST, we look up $(PROD_HOST). The strip is important because whitespace alone is "non-empty" to Make, which can mislead. 

$ make deploy
Makefile:10: *** PROD_HOST is not set.  Stop.
$ make deploy PROD_HOST=mybox
scp release mybox:/opt/

A caveat — the $(error) fires at parse time because it's on the first line of the recipe. If you want it to fire only when deploy is actually run, put the call in a recipe line rather than at the top level. But for this exercise, parse-time is fine.

EX 6.7 medium strip vs :=

Consider:

A := $(shell echo hello)
B := $(strip $(shell echo "  hello  "))

If both assignments store "hello", why do we need strip? Think of a case where the shell output would naturally have leading or trailing whitespace.

Show solution

$(shell) strips trailing newlines and replaces embedded newlines with single spaces. It does not strip leading or trailing spaces. If a command like date or a formatting tool adds padding (some grep -c, for example, or tools on BSDs), $(shell) preserves that padding. If you then compare $(A) to another value, you might get surprising inequality. strip normalises this: one space between words, none at the edges.

EX 6.8 hard Generate rules from a list

Your project has many independent tools in a tools/ directory. Each is a single C file like tools/toolname.c, and each produces a binary bin/toolname. Write a Makefile that automatically generates one rule per tool, without listing them by hand.

Show solution 
TOOL_SRC := $(wildcard tools/*.c)
TOOL_BIN := $(patsubst tools/%.c,bin/%,$(TOOL_SRC))

.PHONY: all clean
all: $(TOOL_BIN)

bin/%: tools/%.c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) $< -o $@

clean: ; rm -rf bin

The pattern rule handles everything. eval is overkill here — patsubst plus a pattern rule is enough. Reach for eval only when the rules truly differ per item (different recipes, different flags) and can't be unified.

Recap

  • Functions: $(func arg1,arg2,...). Commas separate, leading spaces stripped.
  • Text: subst, patsubst, strip, filter, filter-out, sort, findstring, words, word.
  • Files: dir, notdir, suffix, basename, addprefix, addsuffix, realpath, abspath, wildcard.
  • Control flow: $(if), $(or), $(and), $(foreach).
  • User functions: define … endef + $(call).
  • Metaprogramming: $(eval) — evaluate a string as Makefile syntax.
  • Shell: $(shell …) — remember $(.SHELLSTATUS).
  • Diagnostics: $(info), $(warning), $(error). Fire at parse time.
  • Introspection: $(origin), $(flavor), $(value).
  • Files I/O: $(file >NAME,CONTENT).
