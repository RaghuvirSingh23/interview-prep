Chapter 05 Jenkins — Declarative DSL

A full tour of every block in a Declarative Jenkinsfile: parallel, matrix, when, post, options, tools. By the end you'll have a reference you can copy from for every real pipeline.

Parallel execution

Within a stage, parallel splits work across agents:

stage('Test matrix') {
    parallel {
        stage('Unit')        { steps { sh 'make test-unit'  } }
        stage('Integration') { steps { sh 'make test-integ' } }
        stage('Smoke')       { steps { sh 'make test-smoke' } }
    }
}

By default, if any branch fails, the others continue but the stage fails. To stop everything at the first failure:

stage('Test matrix') {
    failFast true
    parallel { ... }
}

Each parallel branch can pin to a different agent:

parallel {
    stage('Linux')   { agent { label 'linux'   }; steps { sh  'make' } }
    stage('macOS')   { agent { label 'macos'   }; steps { sh  'make' } }
    stage('Windows') { agent { label 'windows' }; steps { bat 'msbuild' } }
}

Matrix

When you want to run the same logic over a cartesian product of axes:

stage('Cross-version test') {
    matrix {
        axes {
            axis { name 'NODE'; values '18', '20', '22' }
            axis { name 'OS';   values 'linux', 'macos' }
        }
        excludes {
            exclude { axis { name 'NODE'; values '18' }
                      axis { name 'OS';   values 'macos' } }
        }
        agent { label "${OS}" }
        stages {
            stage('Test') {
                steps {
                    sh 'nvm use $NODE && npm test'
                }
            }
        }
    }
}

That's 3 × 2 = 6 combinations, minus the one exclude = 5 parallel jobs. The axis names become env vars inside each cell.

when — conditional stages

A stage runs only when its when evaluates truthy:

stage('Deploy staging') {
    when { branch 'main' }
    steps { sh './deploy.sh staging' }
}

stage('Deploy prod') {
    when { tag pattern: 'v.*', comparator: 'REGEXP' }
    steps { sh './deploy.sh prod' }
}

All when predicates:

PredicateFires when
branch 'main' Branch name matches (supports globs)
tag 'v*' Build is for a tag matching the pattern
buildingTag() Any tag build
changelog '.*\\[release\\].*' Commit message matches regex
changeset '**/*.py' Changed files match glob
changeRequest() Build is for a PR/MR
environment name: 'X', value: 'y'Env var equals value
expression { ... } Groovy returns truthy
not { ... } Negate
allOf { a; b } All match
anyOf { a; b } At least one matches

Combined:

when {
    allOf {
        branch 'main'
        anyOf { changeset 'src/**'; changeset 'Dockerfile' }
        not { changelog '.*\\[skip-deploy\\].*' }
    }
}

By default, when is evaluated after agent allocation. That means you pay for the agent before deciding to skip. Use beforeAgent true to evaluate first:

when {
    beforeAgent true
    branch 'main'
}

post — conditions for cleanup/notification

Post blocks have named conditions that run depending on build status:

post {
    always    { sh 'rm -rf .cache' }          // runs no matter what
    success   { notifySuccess() }             // all stages succeeded
    failure   { notifyFailure() }             // at least one failed
    unstable  { notifyUnstable() }            // e.g. tests failed but no hard error
    aborted   { notifyAborted() }             // user clicked Abort
    changed   { notifyChanged() }             // status differs from previous build
    fixed     { notifyFixed() }               // went from not-success to success
    regression { notifyBroken() }             // went from success to not-success
    cleanup   { cleanWs() }                  // runs AFTER all other conditions
}

cleanup is special: it always runs, last. Use for workspace cleanup that shouldn't interfere with other notifications.

options — per-build knobs

options {
    // Kill the whole pipeline after 20 min
    timeout(time: 20, unit: 'MINUTES')

    // Prefix log lines with timestamps (needs Timestamper plugin)
    timestamps()

    // ANSI color rendering for recipe output
    ansiColor('xterm')

    // Keep only the last 30 builds
    buildDiscarder(logRotator(numToKeepStr: '30'))

    // If triggered while another build is running, skip new
    disableConcurrentBuilds()

    // Wait for quiet period (useful for rapid commits)
    quietPeriod 10

    // Retry the whole pipeline on failure
    retry(3)

    // Skip the default SCM checkout — lets you manually control checkout
    skipDefaultCheckout(true)

    // Don't echo recipe lines for this step (matches `sh` step 'quiet' option)
    newContainerPerStage()       // only with `agent { docker … }`
}

Stage-level options are a subset — see the official docs. The above are the ones you'll use weekly.

Tools

Jenkins can auto-install common build tools. Go to Manage Jenkins → Tools and configure JDK, Maven, NodeJS (with the NodeJS plugin), etc. Then pull them into any pipeline: 

pipeline {
    agent any
    tools {
        jdk    'openjdk-21'       // matches the name configured in Global Tools
        maven  'maven-3.9'
    }
    stages {
        stage('Build') { steps { sh 'mvn clean verify' } }
    }
}

Jenkins adds them to PATH automatically. Alternatives: Docker-based agents, asdf / mise in shell, or just install on the agent image.

Pipeline environment variables, recap

pipeline {
    agent any
    environment {
        // Plain strings
        SERVICE = 'api'
        VERSION = '1.0.0-${env.BUILD_NUMBER}'   // NB: single-quoted => literal

        // Credentials — auto-masked in logs
        DB         = credentials('staging-db')   // sets DB_USR, DB_PSW, DB
        GITHUB_TOK = credentials('gh-token')     // a 'secret text' credential

        // Derived — can use ${env.X}
        TAG = "${env.SERVICE}-${env.BUILD_NUMBER}"
    }
    stages {
        stage('Show') {
            steps { sh 'echo $SERVICE $DB_USR $TAG' }
        }
    }
}

In environment, single-quoted strings are literal; double-quoted interpolate at pipeline compile time. Inside the recipe, $SERVICE is read by the shell from its environment.

Human-in-the-loop input

stage('Deploy prod') {
    when { branch 'main' }
    steps {
        timeout(time: 1, unit: 'HOURS') {
            input message: 'Deploy to production?',
                  ok: 'Ship it',
                  submitter: 'release-managers',
                  parameters: [
                      choice(name: 'CONFIRM', choices: ['no', 'yes'])
                  ]
        }
        sh './deploy.sh prod'
    }
}

input halts until a permitted user (submitter) clicks the UI button. It holds an executor while waiting — painful on small Jenkins instances. Workaround: wrap the input in a stage with agent none: 

stage('Wait for approval') {
    agent none
    steps { input 'Proceed?' }
}
stage('Deploy') {
    agent any
    steps { sh './deploy.sh' }
}

Docker agents per stage

Run each stage in a specific container:

pipeline {
    agent none
    stages {
        stage('Lint') {
            agent { docker { image 'python:3.11-slim' } }
            steps {
                sh 'pip install ruff && ruff check src/'
            }
        }
        stage('Test') {
            agent { docker { image 'python:3.11-slim'; args '-u 1000' } }
            steps {
                sh 'pip install -r requirements.txt && pytest'
            }
        }
    }
}

Each stage gets a fresh container. The repo is auto-checked-out into the container's workspace. args '-u 1000' runs as UID 1000 (handy to avoid root-owned files in the host workspace).

More sophisticated: agent { dockerfile true } builds a Dockerfile from the repo and uses it as the agent. Perfect when the build tools live in the repo.

A complete, idiomatic Jenkinsfile

groovyJenkinsfile — reference template
pipeline {
    agent none
    options {
        timeout(time: 30, unit: 'MINUTES')
        timestamps()
        ansiColor('xterm')
        buildDiscarder(logRotator(numToKeepStr: '50'))
        disableConcurrentBuilds()
    }
    environment {
        APP        = 'hello-api'
        REGISTRY   = 'registry.example.com/myteam'
    }
    triggers {
        cron(env.BRANCH_NAME == 'main' ? 'H 2 * * *' : '')
    }

    stages {
        stage('Lint') {
            agent { docker { image 'python:3.11-slim' } }
            steps {
                sh 'pip install ruff && ruff check src/'
            }
        }

        stage('Test') {
            parallel {
                stage('Unit') {
                    agent { docker { image 'python:3.11-slim' } }
                    steps {
                        sh '''
                            pip install -r requirements.txt -r requirements-dev.txt
                            pytest --junitxml=reports/unit.xml --cov=src --cov-report=xml
                        '''
                    }
                    post {
                        always { junit 'reports/unit.xml' }
                    }
                }
                stage('Type-check') {
                    agent { docker { image 'python:3.11-slim' } }
                    steps {
                        sh 'pip install mypy && mypy src/'
                    }
                }
            }
        }

        stage('Build image') {
            agent { label 'docker' }
            steps {
                sh "docker build -t ${env.REGISTRY}/${env.APP}:${env.BUILD_NUMBER} ."
            }
        }

        stage('Publish') {
            when { branch 'main' }
            agent { label 'docker' }
            environment { REG_CREDS = credentials('registry-login') }
            steps {
                sh '''
                    echo "$REG_CREDS_PSW" | docker login $REGISTRY -u "$REG_CREDS_USR" --password-stdin
                    docker push $REGISTRY/$APP:$BUILD_NUMBER
                    docker tag  $REGISTRY/$APP:$BUILD_NUMBER $REGISTRY/$APP:latest
                    docker push $REGISTRY/$APP:latest
                '''
            }
        }

        stage('Deploy staging') {
            when { branch 'main' }
            agent { label 'deploy' }
            environment { KUBECONFIG = credentials('staging-kubeconfig') }
            steps {
                sh 'kubectl set image deploy/$APP $APP=$REGISTRY/$APP:$BUILD_NUMBER -n staging'
                sh 'kubectl rollout status deploy/$APP -n staging --timeout=3m'
            }
        }

        stage('Wait for prod approval') {
            when { buildingTag() }
            agent none
            steps {
                timeout(time: 4, unit: 'HOURS') {
                    input message: "Deploy tag ${env.TAG_NAME} to production?",
                          submitter: 'release-managers'
                }
            }
        }

        stage('Deploy prod') {
            when { buildingTag() }
            agent { label 'deploy' }
            environment { KUBECONFIG = credentials('prod-kubeconfig') }
            steps {
                sh 'kubectl set image deploy/$APP $APP=$REGISTRY/$APP:$BUILD_NUMBER -n prod'
                sh 'kubectl rollout status deploy/$APP -n prod --timeout=5m'
            }
        }
    }

    post {
        success {
            slackSend channel: '#ci',
                      color: 'good',
                      message: "✅ ${env.JOB_NAME} #${env.BUILD_NUMBER} succeeded"
        }
        failure {
            slackSend channel: '#ci',
                      color: 'danger',
                      message: "❌ ${env.JOB_NAME} #${env.BUILD_NUMBER} failed"
        }
        cleanup { cleanWs() }
    }
}

Study it. Every block is something we've covered. Adapt it to your project's specifics.

Exercises

EX 5.1 easy Failed-fast matrix

Write a matrix that tests Python 3.9, 3.10, 3.11 on Ubuntu and macOS, and stops all cells as soon as any one fails.

Show solution 
stage('Matrix test') {
    failFast true
    matrix {
        axes {
            axis { name 'PYVER'; values '3.9', '3.10', '3.11' }
            axis { name 'OS';    values 'linux', 'macos' }
        }
        agent { label "${OS}" }
        stages {
            stage('pytest') {
                steps { sh "python${PYVER} -m pytest" }
            }
        }
    }
}
EX 5.2 medium Only when docs changed

Run a "Build docs" stage only when files under docs/ have changed in the commit range being built.

Show solution 
stage('Build docs') {
    when {
        beforeAgent true
        changeset 'docs/**'
    }
    steps { sh 'make -C docs' }
}

changeset compares to the previous successful build. beforeAgent true lets us skip allocating an agent if docs didn't change.

EX 5.3 medium Post conditions

Write a post block that Slacks only when the build goes from failed to success (the recovery notification).

Show solution 
post {
    fixed {
        slackSend channel: '#ci',
                  color: 'good',
                  message: "🎉 ${env.JOB_NAME} recovered: build #${env.BUILD_NUMBER}"
    }
}

fixed is a post-condition that fires only when this build succeeded and the previous didn't.

EX 5.4 hard Approval without holding an executor

Write a pattern where deploying to prod requires approval but doesn't tie up an executor while waiting.

Show solution 
stage('Approval') {
    when { buildingTag() }
    agent none                                   // no executor used
    options { timeout(time: 4, unit: 'HOURS') }  // allow long wait
    steps { input 'Deploy tag to prod?' }
}
stage('Deploy prod') {
    when { buildingTag() }
    agent { label 'deploy' }
    steps { sh './deploy.sh prod' }
}

agent none at the stage level means Jenkins doesn't hold an executor during the wait — useful on busy instances where executors are scarce.

EX 5.5 medium Dockerfile-based agent

Your repo has a Dockerfile.ci defining the exact environment the build needs. Configure a Declarative pipeline to build and use that image as the agent.

Show solution 
pipeline {
    agent {
        dockerfile {
            filename 'Dockerfile.ci'
            dir '.'
            label 'docker'
        }
    }
    stages {
        stage('Build') { steps { sh 'make' } }
    }
}

Jenkins builds the image (cached on the agent), starts a container, mounts the workspace, and runs steps inside. Perfect hermeticity — the build environment is versioned with the code.

EX 5.6 hard Cron that varies by branch

Schedule nightly builds only on main, not feature branches. Declarative triggers is set at pipeline scope — how?

Show solution 
pipeline {
    agent any
    triggers {
        cron(env.BRANCH_NAME == 'main' ? 'H 2 * * *' : '')
    }
    // ...
}

An empty cron string means "no schedule". The conditional is evaluated per branch in a multibranch pipeline, so only the main branch's job has the schedule installed.

Recap

  • parallel within a stage; add failFast true to stop on first failure.
  • matrix for cartesian products of axes; excludes to trim the grid.
  • when with branch, tag, changeset, changeRequest(), etc. beforeAgent true avoids allocating agents for skipped stages.
  • post conditions: always, success, failure, fixed, cleanup, and others.
  • options for timeouts, log rotation, concurrency, ANSI colors.
  • tools auto-installs JDKs/Maven/Node without shell gymnastics.
  • agent { docker … } or agent { dockerfile … } gives hermetic per-stage environments.
  • input for approvals; use agent none to avoid holding an executor.
