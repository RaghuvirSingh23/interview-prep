A Deep Dive C, C++, Linux, and the art of debugging.

The toolkit for systems programmers: C and C++ as they actually work (not as the textbooks pretend), the Linux APIs you reach for every week, and the debugging techniques that turn a six-hour detective story into a thirty-minute fix. Threading, sanitizers, GDB, perf, eBPF — all of it. Pointed at people who already know how to write a function but want to debug a segfault on a Tuesday night and not panic.

14 chapters 3 domains 80+ exercises 50 interview Qs

How this is organised

  • Chapters 1–3 — The languages. C as a careful subset, C++ as a modern subset (RAII, smart pointers, move), the memory model and undefined behaviour you'll dance around forever.
  • Chapter 4 — Build & link. Translation units, ELF, symbols, static vs dynamic libs, the linker errors that read like ancient runes.
  • Chapters 5–8 — The Linux APIs. Process model, files & I/O, threads & atomics, IPC and sockets — the system calls you'll trace on every job.
  • Chapter 9 — Performance & observability. perf, strace, eBPF/bpftrace, flamegraphs, cache effects, the difference between "slow" and "actually slow".
  • Chapters 10–12 — Debugging. GDB cover-to-cover, the sanitizers (ASan/TSan/UBSan/MSan/valgrind), and the kernel-adjacent tricks (kgdb, kprobes, ftrace, dmesg, JTAG).
  • Chapter 13 — The 50 Questions. Interview-style answers across the lot.
  • Chapter 14 — Capstone. A deliberately-broken multi-threaded C++ program: race + UB + leak + signal-handler bug. You diagnose every problem with the right tool.
Prerequisites
  • You've written some C or C++. You know what a pointer is, even if you don't always trust them.
  • A Linux machine. Real, VM, WSL2, or container — any modern distro will do. macOS works for most of it; Linux-specific bits (perf, eBPF, /proc) need actual Linux.
  • gcc or clang, make, gdb, valgrind. We'll install the rest as we go.
  • Comfort at the shell. ls, grep, find should be reflex.
