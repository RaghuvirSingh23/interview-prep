Chapter 08 IPC & sockets

Pipes, Unix-domain sockets, shared memory, and TCP/UDP. The building blocks behind every server and every multi-process system on the box. Plus epoll — the event-loop primitive Linux servers are built on.

Pick the right IPC

MechanismUse when
Pipes (anonymous)Parent ↔ child, one direction, byte stream. shell | uses these.
FIFOs (named pipes)Unrelated processes, byte stream, one writer/reader at a time. Uncommon.
Unix-domain socketsLocal IPC; bidirectional; messages or stream; can pass fds and credentials. Default for any local IPC you design.
POSIX message queuesPriority-ordered messages between processes. Niche; sockets usually win.
Shared memory (POSIX shm_open or SysV)Bulk data sharing without copies. Pair with a mutex/futex/semaphore.
eventfdCounter you can poll on. Cheap "wake up the event loop" primitive.
signalfdReceive signals via a file descriptor.
timerfdTimers as fds — integrates with epoll.
TCP/UDPCross-host networking. Localhost too if you need network-shaped semantics.

For new local IPC, default to a Unix-domain socket. They're fast (no TCP/IP stack), pass fds, deliver peer credentials (SO_PEERCRED), and have the same API as network sockets — easy to extend later.

Unix-domain sockets — the standard local IPC

cserver.c
#include <sys/socket.h>
#include <sys/un.h>
#include <unistd.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    int s = socket(AF_UNIX, SOCK_STREAM | SOCK_CLOEXEC, 0);
    struct sockaddr_un addr = { .sun_family = AF_UNIX };
    strcpy(addr.sun_path, "/tmp/myapp.sock");
    unlink(addr.sun_path);                                  // remove stale
    bind(s, (struct sockaddr *)&addr, sizeof addr);
    listen(s, 16);

    for (;;) {
        int c = accept4(s, NULL, NULL, SOCK_CLOEXEC);
        char buf[4096];
        ssize_t n = read(c, buf, sizeof buf);
        write(c, buf, n);          // echo
        close(c);
    }
}
cclient.c
int s = socket(AF_UNIX, SOCK_STREAM | SOCK_CLOEXEC, 0);
struct sockaddr_un addr = { .sun_family = AF_UNIX };
strcpy(addr.sun_path, "/tmp/myapp.sock");
connect(s, (struct sockaddr *)&addr, sizeof addr);
write(s, "hello", 5);
char buf[64];
ssize_t n = read(s, buf, sizeof buf);
buf[n] = '\0';
puts(buf);                          // "hello"
close(s);

Things to know:

  • SOCK_STREAM = byte stream, like TCP. SOCK_DGRAM = messages with boundaries, like UDP. SOCK_SEQPACKET = reliable messages with boundaries.
  • Abstract sockets on Linux: pathnames starting with \0 live in a separate namespace (no filesystem entry). Useful for unprivileged servers.
  • SO_PEERCRED tells you the connecting process's PID/UID/GID. Authenticate without passwords.
  • Pass file descriptors through Unix sockets with SCM_RIGHTS. Useful for "give me an open log file" patterns.

Passing file descriptors

This is one of Unix's underused superpowers. The kernel duplicates the fd into the receiver's table. Used by privileged-helper patterns: a privileged process opens a low port socket and hands it to a worker.

// Sender
struct msghdr msg = {0};
struct iovec  iov = { .iov_base = "hi", .iov_len = 2 };
char cbuf[CMSG_SPACE(sizeof(int))];
msg.msg_iov     = &iov; msg.msg_iovlen = 1;
msg.msg_control = cbuf;  msg.msg_controllen = sizeof cbuf;
struct cmsghdr *cm = CMSG_FIRSTHDR(&msg);
cm->cmsg_level = SOL_SOCKET; cm->cmsg_type = SCM_RIGHTS;
cm->cmsg_len = CMSG_LEN(sizeof(int));
memcpy(CMSG_DATA(cm), &fd_to_send, sizeof(int));
sendmsg(sock, &msg, 0);

// Receiver — symmetric, recvmsg pulls the fd into your table at a new number.

Painful API; the win is real. Systemd, browsers (sandboxed renderer + privileged main), libvirt all use this.

Shared memory

#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>

int fd = shm_open("/myapp_shm", O_RDWR | O_CREAT | O_CLOEXEC, 0600);
ftruncate(fd, 4096 * 1024);
void *p = mmap(NULL, 4096 * 1024, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
close(fd);
// Both processes that shm_open the same name see the same memory.

POSIX shared memory lives at /dev/shm/myapp_shm on Linux — it's a tmpfs file. Same lifecycle: shm_unlink to remove. Pair with a futex or a process-shared mutex (PTHREAD_PROCESS_SHARED) for synchronisation.

Care: shared-memory layouts cross process boundaries. Different builds with different struct layouts will misread. Pin the binary, or version the format.

futex — the kernel side of mutexes

A futex (fast userspace mutex) is the syscall std::mutex, pthread_mutex, std::condition_variable, and friends are built on. The fast path stays in userspace; only contention goes to the kernel.

Direct futex use is rare — use std::mutex or pthread_mutex_t. But you'll see futexes in strace output and in the implementation of every locking primitive. Knowing what they are makes futex(...) in stack traces stop looking scary.

eventfd, timerfd, signalfd — the unifying trick

Linux exposes signals, timers, and "wakeup" notifications as file descriptors so they integrate with poll/epoll. This is how modern event loops avoid mixing async signals with synchronous I/O.

// eventfd — counter, write to wake any reader
int e = eventfd(0, EFD_CLOEXEC | EFD_NONBLOCK);
uint64_t v = 1; write(e, &v, sizeof v);   // wakes the reader

// timerfd — periodic timer as fd
int t = timerfd_create(CLOCK_MONOTONIC, TFD_CLOEXEC | TFD_NONBLOCK);
struct itimerspec ts = {
    .it_interval = {.tv_sec = 1},  // every 1s
    .it_value    = {.tv_sec = 1},  // first fire 1s from now
};
timerfd_settime(t, 0, &ts, NULL);

// signalfd — read signal info from an fd; see chapter 5

Plug all three into your epoll loop and you never have to deal with async signal handlers, callback-style timers, or condvar wake-ups in the same loop as your sockets.

TCP sockets — server skeleton

#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <unistd.h>
#include <string.h>

int main(void) {
    int s = socket(AF_INET, SOCK_STREAM | SOCK_CLOEXEC, 0);

    int yes = 1;
    setsockopt(s, SOL_SOCKET, SO_REUSEADDR, &yes, sizeof yes);
    setsockopt(s, SOL_SOCKET, SO_REUSEPORT, &yes, sizeof yes);   // Linux: load-balance across multiple listeners

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port   = htons(8080),
        .sin_addr   = { htonl(INADDR_ANY) },
    };
    bind(s, (struct sockaddr *)&addr, sizeof addr);
    listen(s, 128);

    for (;;) {
        struct sockaddr_in cli;
        socklen_t cl = sizeof cli;
        int c = accept4(s, (struct sockaddr *)&cli, &cl, SOCK_CLOEXEC);
        // ... handle client; ideally hand to a worker or epoll loop
    }
}

Defaults you'll set on most servers:

  • SO_REUSEADDR — restart the server without "address already in use" for ~minute.
  • SO_REUSEPORT — multiple processes/threads bind the same port; kernel load-balances incoming connections.
  • TCP_NODELAY — disable Nagle, lower latency for small messages (web, RPC).
  • SO_KEEPALIVE + TCP_KEEPIDLE/TCP_KEEPINTVL/TCP_KEEPCNT — detect dead peers.
  • O_NONBLOCK on the fd if you're using epoll.

UDP — the connectionless cousin

int s = socket(AF_INET, SOCK_DGRAM | SOCK_CLOEXEC, 0);
bind(s, ...);

for (;;) {
    char buf[1500];
    struct sockaddr_in cli;
    socklen_t cl = sizeof cli;
    ssize_t n = recvfrom(s, buf, sizeof buf, 0, (struct sockaddr *)&cli, &cl);
    sendto(s, buf, n, 0, (struct sockaddr *)&cli, cl);  // echo
}

UDP datagrams are atomic — one recv reads exactly one datagram (or you lose the rest with truncation). Lost packets aren't retransmitted; ordering isn't preserved. You build reliability if you need it (DNS, QUIC, VPNs do).

epoll — wait for many fds at once

poll works but scans all fds linearly. epoll is the Linux scaling answer: O(1) registration, O(ready) wakeup.

#include <sys/epoll.h>

int ep = epoll_create1(EPOLL_CLOEXEC);

struct epoll_event ev = { .events = EPOLLIN | EPOLLET, .data.fd = listen_fd };
epoll_ctl(ep, EPOLL_CTL_ADD, listen_fd, &ev);

struct epoll_event evs[64];
for (;;) {
    int n = epoll_wait(ep, evs, 64, -1);
    for (int i = 0; i < n; i++) {
        int fd = evs[i].data.fd;
        if (fd == listen_fd) {
            int c = accept4(listen_fd, NULL, NULL, SOCK_CLOEXEC | SOCK_NONBLOCK);
            ev.events = EPOLLIN | EPOLLET;
            ev.data.fd = c;
            epoll_ctl(ep, EPOLL_CTL_ADD, c, &ev);
        } else {
            handle_io(fd);
        }
    }
}

Two trigger modes:

  • Level-triggered (default): the fd reports ready as long as data is available. Easier to write correctly; small CPU overhead from spurious wake-ups.
  • Edge-triggered (EPOLLET): reports ready only on transitions. You must read until EAGAIN on every event, or you'll deadlock waiting for an event that already came. Faster; harder to use.

Modern Linux servers (nginx, redis, envoy) use epoll-ET with O_NONBLOCK sockets. The library you use (libuv, asio, tokio for Rust) hides the details.

io_uring — the modern next step

io_uring (kernel 5.1+) is the latest async-I/O interface — submission and completion queues shared with the kernel. Saves syscalls, supports a wide range of ops including network, file, fsync, splice. liburing is the user-friendly wrapper.

For very high-throughput servers, io_uring beats epoll. For typical applications, epoll is fine; io_uring is the right answer when you've measured and have evidence.

Inspecting connections

$ ss -tlnp                          # listening TCP, with PID
State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port  Process
LISTEN  0       128     0.0.0.0:8080         0.0.0.0:*          users:(("myapp",pid=1234,fd=3))

$ ss -tan state established        # all established TCP
$ ss -lx                            # listening unix sockets

$ ss -i src :8080                   # detailed: cwnd, rtt, retransmits
$ ss -K dst 1.2.3.4                 # kill connections (root)

$ tcpdump -i lo -A 'port 8080'      # packet capture; -A shows ASCII
$ tcpdump -i any -w trace.pcap      # save for Wireshark

ss replaces the older netstat. tcpdump + Wireshark for the wire-level details. Both are reflex tools.

Network gotchas

  • SIGPIPE on closed peer: covered in chapter 5. Ignore the signal or use MSG_NOSIGNAL.
  • TIME_WAIT after server restart: fixed by SO_REUSEADDR on listening socket.
  • Partial writes / reads: TCP is a byte stream; one send may take multiple recvs and vice versa. Frame your messages (length-prefix or delimiter).
  • Nagle + delayed-ACK can cause 40 ms latency on small request/response. Set TCP_NODELAY for interactive protocols.
  • Slow loris / accept queue: attackers connecting and not sending fill your listen() backlog. TCP_DEFER_ACCEPT on Linux lets the kernel hold the connection until data arrives.
  • Reverse-DNS lookups in your server: blocking, slow, often hostile. Don't.
  • EINTR: just like file I/O — retry, or use SA_RESTART.

Exercises

EX 8.1 easy TCP framing

You send three messages over TCP: "ALPHA", "BETA", "GAMMA". The receiver might read them as one chunk "ALPHABETAGAMMA". Why, and how do you frame so the receiver gets three?

Show solution

TCP is a byte stream; it doesn't preserve send boundaries. The kernel coalesces small sends; the receiver's read returns whatever's available. Two framing options:

  1. Length-prefix: 4-byte big-endian length, then payload. Read length, then exactly that many bytes.
  2. Delimiter: e.g. newline. Read until you see one. HTTP/1.1 uses both (Content-Length or chunked).

SOCK_DGRAM (UDP, AF_UNIX SOCK_DGRAM, SEQPACKET) preserves boundaries — but with size limits and other tradeoffs.

EX 8.2 medium SO_REUSEADDR vs SO_REUSEPORT
Show solution
  • SO_REUSEADDR: lets you bind a port that's in TIME_WAIT from a recent close. Solves the "address already in use" annoyance after server restart. Required on every server.
  • SO_REUSEPORT: Linux 3.9+. Multiple processes/threads can bind the same address+port; the kernel hashes incoming connections across them. Used for "N-process server with no connection broker". Each accept goes to one binder; no thundering herd.

Set both on a listening socket. They solve different problems.

EX 8.3 medium Pick the IPC

Pick the right primitive:

  1. A privileged helper opens hardware devices and hands fds to a worker process.
  2. A producer writes 100 MB/s to a consumer in another process; both on same machine.
  3. You want to wake an event loop from another thread.
  4. A daemon needs to receive SIGTERM cleanly along with TCP traffic in one loop.
Show solution
  1. Unix-domain socket with SCM_RIGHTS — pass fds.
  2. Shared memory ring + semaphore/futex (or eventfd as the wake). Avoids copy.
  3. eventfd. Cheap, integrates with epoll.
  4. signalfd in the epoll loop. Block the signals normally, deliver via fd.
EX 8.4 hard Authenticate over Unix socket

Your local daemon should serve only callers running as a specific user. Don't use passwords. How?

Show solution 
#include <sys/socket.h>

struct ucred peer;
socklen_t len = sizeof peer;
if (getsockopt(client_fd, SOL_SOCKET, SO_PEERCRED, &peer, &len) < 0) {
    /* error */
}
/* peer.pid, peer.uid, peer.gid */
if (peer.uid != EXPECTED_UID) {
    close(client_fd);
    return -1;
}

The kernel guarantees the credentials of the connecting process. The caller can't lie. Pair with restrictive socket-file permissions (chmod 0600) and you've got user-level authentication for free.

EX 8.5 hard Mystery latency

Your RPC server processes requests in < 1 ms locally, but clients see 40 ms latency. tcpdump shows the client's request goes out fine; the server response arrives 40 ms later than the server logs claim it sent. What's likely?

Show solution

Nagle's algorithm + delayed-ACK interaction. Server sends a small response; the client's TCP stack is in delayed-ACK mode (waiting up to 40 ms to piggyback an ACK on data). Server's Nagle won't send the next small chunk until ACK'd. Result: 40 ms idle.

Fix: setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &one, sizeof one) on both sides. Required for any interactive RPC over TCP.

Recap

  • Default to Unix sockets for local IPC; same API as TCP, plus fd passing and peer credentials.
  • Shared memory + futex/process-shared mutex for bulk data.
  • eventfd / signalfd / timerfd unify async events with file-descriptor I/O for clean event loops.
  • TCP gotchas: framing (it's a stream), TIME_WAIT (use SO_REUSEADDR), Nagle×delayed-ACK (TCP_NODELAY), SIGPIPE (ignore or MSG_NOSIGNAL).
  • epoll is the scalable wait-for-fds. Edge-triggered for performance, level-triggered for simplicity.
  • ss + tcpdump + Wireshark are the inspection tools.
