Chapter 05 CLIs & Packaging

Turning a script into a tool — argument parsing, console-script entry points, modern packaging with pyproject.toml and uv, testing with pytest, and shipping a Docker image. The shape of every Python tool you'll write at work.

argparse — std-lib, perfectly fine

import argparse
from pathlib import Path

def build_parser() -> argparse.ArgumentParser:
    p = argparse.ArgumentParser(
        prog="promote",
        description="Promote artifacts between channels",
    )
    p.add_argument("--version", action="version", version="promote 1.0.0")

    sub = p.add_subparsers(dest="cmd", required=True)

    a = sub.add_parser("artifact", help="Manage artifacts")
    a.add_argument("name")
    a.add_argument("--from", dest="src", required=True,
                   choices=["dev", "staging"])
    a.add_argument("--to",   dest="dst", required=True,
                   choices=["staging", "release"])
    a.add_argument("--dry-run", action="store_true")
    a.add_argument("--verbose", "-v", action="count", default=0)
    a.add_argument("--manifest", type=Path, help="Path to manifest.json")

    sub.add_parser("list", help="List artifacts in each channel")

    return p

def main(argv: list[str] | None = None) -> int:
    args = build_parser().parse_args(argv)
    if args.cmd == "artifact":
        ...
    elif args.cmd == "list":
        ...
    return 0

if __name__ == "__main__":
    raise SystemExit(main())

argparse covers 95% of needs. Pass argv in tests rather than reading sys.argv.

typer — argparse with types

If you want type-driven argument parsing for free, typer is hard to beat:

import typer
from pathlib import Path
from typing import Annotated

app = typer.Typer(no_args_is_help=True)

@app.command()
def artifact(
    name: str,
    src: Annotated[str, typer.Option("--from")] = "dev",
    dst: Annotated[str, typer.Option("--to")]   = "staging",
    dry_run: bool = False,
    manifest: Path | None = None,
):
    """Promote ARTIFACT from --from channel to --to channel."""
    print(f"promoting {name}: {src} → {dst}")
    if dry_run:
        return
    ...

@app.command(name="list")
def list_():
    """List artifacts in each channel."""
    ...

if __name__ == "__main__":
    app()

Type hints become argument types. Docstrings become --help text. Subcommands are just decorated functions. Same kind of project as fastapi, by the same author.

click — battle-tested workhorse

What typer wraps under the hood. Worth knowing because most pre-2020 Python CLIs use it.

import click
from pathlib import Path

@click.group()
def cli(): pass

@cli.command()
@click.argument("name")
@click.option("--from", "src", required=True, type=click.Choice(["dev", "staging"]))
@click.option("--to",   "dst", required=True, type=click.Choice(["staging", "release"]))
@click.option("--dry-run", is_flag=True)
@click.option("--manifest", type=click.Path(exists=True, path_type=Path))
def promote(name, src, dst, dry_run, manifest):
    """Promote NAME from --from to --to."""
    ...

if __name__ == "__main__":
    cli()

Pick one of the three and stick with it. Mixing them in the same project is needless cognitive overhead.

Exit codes that mean something

EXIT_OK            = 0
EXIT_GENERIC_FAIL  = 1
EXIT_CONFIG_ERROR  = 2
EXIT_AUTH_FAILED   = 3
EXIT_NOT_FOUND     = 4
EXIT_INTERRUPTED   = 130    # Unix convention for SIGINT

def main() -> int:
    try:
        run()
        return EXIT_OK
    except KeyboardInterrupt:
        return EXIT_INTERRUPTED
    except FileNotFoundError as e:
        log.error("not found: %s", e); return EXIT_NOT_FOUND
    except AuthenticationError:
        log.error("auth failed"); return EXIT_AUTH_FAILED
    except Exception:
        log.exception("unexpected"); return EXIT_GENERIC_FAIL

if __name__ == "__main__":
    raise SystemExit(main())

Distinct exit codes let scripts that wrap your tool act sensibly: ./promote …; if [ $? = 4 ]; then …. raise SystemExit(rc) at the bottom is the idiom — preserves finally handlers, unlike sys.exit(rc) from anywhere.

Project layout

promote/
├── pyproject.toml           # build & metadata
├── README.md
├── LICENSE
├── src/
│   └── promote/             # the package — same name as the project
│       ├── __init__.py
│       ├── __main__.py      # `python -m promote`
│       ├── cli.py
│       ├── client.py
│       └── config.py
└── tests/
    ├── test_cli.py
    └── test_client.py

Use src/<package>/ layout (not the flat ./<package>/). The src layout prevents accidentally importing your in-development package because the cwd is on sys.path; you have to install it (even pip install -e .) before import promote works. That's a feature.

pyproject.toml — modern packaging

tomlpyproject.toml
[build-system]
requires      = ["hatchling"]
build-backend = "hatchling.build"

[project]
name        = "promote"
version     = "1.0.0"
description = "Promote artifacts between channels"
requires-python = ">=3.11"
license     = "MIT"
authors     = [{name = "Your Name", email = "you@example.com"}]
readme      = "README.md"

dependencies = [
    "requests >= 2.31",
    "pydantic >= 2.5",
    "typer >= 0.12",
    "ruamel.yaml >= 0.18",
]

[project.optional-dependencies]
dev = [
    "pytest >= 8",
    "pytest-cov",
    "mypy",
    "ruff",
]

[project.scripts]
promote = "promote.cli:app"          # creates a `promote` command on install

[tool.hatch.build.targets.wheel]
packages = ["src/promote"]

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "S"]   # pycodestyle, pyflakes, isort, bugbear, pyupgrade, security

[tool.mypy]
strict = true
python_version = "3.11"

[tool.pytest.ini_options]
addopts  = "-q --strict-markers"
testpaths = ["tests"]

Highlights:

  • [project.scripts] creates a real CLI executable on install. pip install . → promote is on $PATH.
  • Optional dependencies with [project.optional-dependencies] let you split dev, test, docs. Install with pip install -e ".[dev]".
  • Tool config in [tool.X] sections — ruff, mypy, pytest all read from here. One file owns everything.

uv — the fast modern installer

uv (by Astral, of Ruff fame) replaces pip + venv + pip-tools + pyenv with one Rust binary that's 10-100× faster. The 2026 default for new Python projects.

# Install uv (one-time)
$ curl -LsSf https://astral.sh/uv/install.sh | sh

# In a project
$ uv venv                              # create .venv
$ uv pip install -e ".[dev]"           # install with extras
$ uv pip compile pyproject.toml -o requirements.lock
$ uv pip sync requirements.lock        # exact-match install

# Or the workflow API
$ uv add requests pydantic             # adds + installs + updates lockfile
$ uv run pytest                        # runs in the project's venv automatically
$ uv build                             # builds sdist + wheel

Drop-in for most pip workflows. Try it; you won't go back.

Lockfiles

"Pin all dependencies including transitive ones at exact versions, with hashes." Run pip install from a lockfile and you get bit-for-bit identical environments.

$ uv pip compile pyproject.toml --output-file requirements.lock --generate-hashes
# requirements.lock now has every package + transitive at exact pinned version + sha256 hashes

$ uv pip sync requirements.lock        # install exactly what's in the lock

Commit the lockfile. CI installs from it. Bumps go through PRs. This is what stops "Tuesday's build was green, Wednesday's broke because some transitive dep released a bad version."

Testing — pytest essentials

pythontests/test_client.py
import pytest
from promote.client import ArtifactoryClient, ArtifactNotFound

def test_normalise_url_strips_trailing_slash():
    c = ArtifactoryClient("https://art.example.com/", token="x")
    assert c.base == "https://art.example.com"

def test_promote_missing_raises(monkeypatch):
    c = ArtifactoryClient("https://art.example.com", token="x")
    monkeypatch.setattr(c, "get", lambda path: (_ for _ in ()).throw(ArtifactNotFound("nope")))
    with pytest.raises(ArtifactNotFound):
        c.promote("foo", "dev", "staging")

@pytest.fixture
def fake_repo(tmp_path):
    """A tmp directory shaped like our repo layout."""
    (tmp_path / "manifest.json").write_text('{"sha":"abc"}')
    return tmp_path

def test_load_config(fake_repo):
    cfg = load_config(fake_repo / "manifest.json")
    assert cfg.sha == "abc"

@pytest.mark.parametrize("src,dst,ok", [
    ("dev", "staging", True),
    ("staging", "release", True),
    ("dev", "release", False),                 # skip a level
    ("release", "dev", False),                 # backwards
])
def test_promotion_paths(src, dst, ok):
    assert is_valid_promotion(src, dst) is ok

Key features:

  • Fixtures via @pytest.fixture — set up state, return it, optionally tear down.
  • tmp_path — built-in fixture that gives a fresh Path per test. No more os.tmpdir dance.
  • monkeypatch — replace attributes/env vars for one test, auto-restored.
  • parametrize — run the same test against multiple inputs.
  • capsys for capturing stdout/stderr; caplog for log records.

Containerise the CLI

Distroless or slim Python base + multi-stage build for tiny images.

dockerfileDockerfile
# --- stage 1: builder ---
FROM python:3.12-slim AS build
WORKDIR /app
RUN pip install --no-cache-dir uv
COPY pyproject.toml requirements.lock ./
RUN uv pip install --system --no-cache --requirements requirements.lock
COPY src/ ./src/
RUN uv pip install --system --no-cache .

# --- stage 2: runtime ---
FROM python:3.12-slim
RUN useradd -r -u 10001 app
COPY --from=build /usr/local/lib/python3.12/site-packages \
                  /usr/local/lib/python3.12/site-packages
COPY --from=build /usr/local/bin/promote /usr/local/bin/promote
USER 10001
ENTRYPOINT ["promote"]

Multi-stage so the final image carries only runtime, not build tools (no uv, no source). Non-root user. Final image around 70 MB.

EX 5.2 medium Subcommands with argparse

Build an argparse-based CLI with subcommands build, test, publish, each with its own flags.

Show solution 
import argparse

def main():
    p = argparse.ArgumentParser()
    sub = p.add_subparsers(dest="cmd", required=True)

    b = sub.add_parser("build")
    b.add_argument("--target", required=True)

    t = sub.add_parser("test")
    t.add_argument("--coverage", action="store_true")

    pub = sub.add_parser("publish")
    pub.add_argument("--channel", choices=["dev", "staging", "release"])

    args = p.parse_args()
    if args.cmd == "build":   build(args.target)
    elif args.cmd == "test":   test(args.coverage)
    elif args.cmd == "publish": publish(args.channel)

EX 5.5 hard Lockfile-driven CI

Set up a GitHub Actions workflow that fails the build if the lockfile is out of sync with pyproject.toml. Why is this useful?

Show solution 
- run: |
    uv pip compile pyproject.toml -o /tmp/check.lock
    diff -u requirements.lock /tmp/check.lock

Catches drift: someone added a dependency to pyproject.toml without regenerating the lockfile, so CI installs the old set. The diff fails the build and surfaces the mistake.

Recap

  • Pick one CLI lib (argparse / typer / click) and stick with it. Pass argv into main() so tests can drive it.
  • Use distinct exit codes; wrap with raise SystemExit(rc).
  • src/<package>/ layout, pyproject.toml for everything, [project.scripts] for console entry points.
  • uv replaces pip+venv+pip-tools at 10–100× speed.
  • Lockfiles with hashes, committed to git, used in CI.
  • Pytest with fixtures, parametrize, and HTTP mocking.
  • Multi-stage Docker for tiny final images, non-root user.
