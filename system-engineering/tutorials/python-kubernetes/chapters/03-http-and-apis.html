Chapter 03 HTTP & APIs

Talking to APIs is 80% of automation work. requests for most things, httpx when you need async or HTTP/2, retries that don't lie, sessions that pool connections, auth that doesn't leak. The patterns here scale from a 10-line script to a service.

requests — the basics

import requests

# GET
r = requests.get("https://api.github.com/repos/torvalds/linux")
r.raise_for_status()                  # raise on 4xx/5xx
data = r.json()
print(data["full_name"], data["stargazers_count"])

# POST JSON
r = requests.post(
    "https://api.example.com/v1/items",
    json={"name": "fw-1.0.0", "channel": "dev"},
    headers={"Authorization": f"Bearer {token}"},
    timeout=10,
)
r.raise_for_status()

Five rules from day one:

  1. Always pass timeout=. Without it, a hung server hangs your script forever.
  2. Always call raise_for_status(). Otherwise r.json() on a 500 page silently parses HTML as JSON and gives garbage.
  3. Use json=, not data=json.dumps(...). Sets the right header automatically.
  4. Stream big responses with stream=True + iter_content; otherwise the whole body lands in memory.
  5. Use a Session for anything that does >1 request — connection pooling alone is a 5-10× speedup.

Sessions

import requests

class ArtifactoryClient:
    def __init__(self, base: str, token: str):
        self.base = base.rstrip('/')
        self.s = requests.Session()
        self.s.headers.update({
            "Authorization": f"Bearer {token}",
            "Accept": "application/json",
            "User-Agent": "promote-bot/1.0",
        })

    def get(self, path: str, **kw):
        r = self.s.get(f"{self.base}{path}", timeout=15, **kw)
        r.raise_for_status()
        return r.json()

    def promote(self, src: str, dst: str) -> None:
        r = self.s.post(
            f"{self.base}/api/copy/{src}",
            params={"to": dst, "dry": 0},
            timeout=60,
        )
        r.raise_for_status()

The Session reuses the underlying TCP connection (and TLS handshake) across requests. For dozens of calls, the difference between session and no-session is the difference between a 30-second job and a 3-second job.

Timeouts — read them carefully

timeout=10 is shorthand for 10 seconds for both connect and read. The two-tuple form is more nuanced:

requests.get(url, timeout=(3.05, 30))     # (connect, read)

Use a short connect timeout (3-5 s) and a longer read timeout (30+ s) for endpoints that do real work. The 3.05 oddity is because TCP retransmit cycles align with multiples of 3 seconds.

Retries that work

The naïve loop is wrong:

# BAD — no backoff, retries on every error including 4xx
for _ in range(5):
    try:
        return requests.get(url).json()
    except Exception:
        continue
raise RuntimeError("gave up")

Use urllib3's Retry via a session adapter — battle-tested, handles backoff, picks correct status codes:

from requests import Session
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

def make_session() -> Session:
    s = Session()
    retry = Retry(
        total=5,
        backoff_factor=0.5,                # 0.5, 1, 2, 4, 8 seconds
        status_forcelist=(429, 500, 502, 503, 504),
        allowed_methods=("HEAD", "GET", "PUT", "DELETE", "OPTIONS", "POST"),
        respect_retry_after_header=True,
    )
    adapter = HTTPAdapter(max_retries=retry, pool_connections=20, pool_maxsize=20)
    s.mount("https://", adapter)
    s.mount("http://", adapter)
    return s

Backoff: each attempt sleeps backoff_factor * (2 ** (attempt-1)), plus jitter from server's Retry-After. Don't retry POSTs that aren't idempotent — set allowed_methods=("GET", "PUT", "DELETE") if your POSTs would be unsafe to repeat.

Idempotency keys

For POSTs that create things, you want safe-to-retry semantics. The convention: send a unique header so the server can dedupe.

import uuid

key = str(uuid.uuid4())
r = session.post(
    "https://api.example.com/promotions",
    json={"artifact": name, "channel": "release"},
    headers={"Idempotency-Key": key},
    timeout=30,
)

If the network breaks mid-request and you retry with the same key, the server returns the original result instead of creating a duplicate. Stripe popularised this; many modern APIs support it.

Auth patterns

Bearer tokens (most common)

session.headers["Authorization"] = f"Bearer {token}"

Basic auth

requests.get(url, auth=(user, password))

API key in header

session.headers["X-Api-Key"] = api_key

OAuth2 — client credentials flow

def fetch_token(client_id: str, client_secret: str, token_url: str) -> tuple[str, float]:
    r = requests.post(
        token_url,
        data={"grant_type": "client_credentials"},
        auth=(client_id, client_secret),
        timeout=10,
    )
    r.raise_for_status()
    body = r.json()
    return body["access_token"], time.time() + body["expires_in"] - 30   # 30s safety

Cache the token; refresh when it's about to expire. Don't fetch a fresh token per request — that's a flood of auth calls and gets you rate-limited.

mTLS (client certificate)

requests.get(url, cert=("client.crt", "client.key"), verify="ca.pem")

Streaming downloads & uploads

Stream-download a 5 GB image

def download(url: str, dst: Path, session: Session) -> None:
    with session.get(url, stream=True, timeout=(10, 600)) as r:
        r.raise_for_status()
        tmp = dst.with_suffix(dst.suffix + ".part")
        with tmp.open("wb") as f:
            for chunk in r.iter_content(chunk_size=1 << 20):    # 1 MB
                f.write(chunk)
        tmp.replace(dst)                                          # atomic

Stream-upload a file (no double-buffering)

with open("firmware.img", "rb") as f:
    r = session.put(
        url,
        data=f,                          # streaming generator-like
        headers={"Content-Type": "application/octet-stream"},
        timeout=(10, 1800),
    )
    r.raise_for_status()

Don't read() a 5 GB file then pass data=bytes — you'll OOM. Pass the file handle and requests streams it.

Pagination

The two common API styles:

Link-header (RFC 5988) — GitHub, GitLab

def paginate(session, url):
    while url:
        r = session.get(url, timeout=15)
        r.raise_for_status()
        yield from r.json()
        url = r.links.get("next", {}).get("url")    # parsed Link header

repos = list(paginate(s, "https://api.github.com/orgs/myorg/repos?per_page=100"))

Cursor / token — common everywhere else

def paginate_cursor(session, url, params):
    params = dict(params)
    while True:
        r = session.get(url, params=params, timeout=15)
        r.raise_for_status()
        body = r.json()
        yield from body["items"]
        if not body.get("next_token"):
            break
        params["page_token"] = body["next_token"]

Generators here mean memory stays flat regardless of total result count.

Rate limiting

Most APIs publish their limits in headers:

r = session.get(url)
remaining = int(r.headers.get("X-RateLimit-Remaining", "1"))
reset_ts  = int(r.headers.get("X-RateLimit-Reset", "0"))
if remaining < 5:
    log.warning("rate limit close: %d left, resets at %d", remaining, reset_ts)

For client-side throttling, tenacity and asyncio-based aiolimiter are good libraries.

Error handling

import requests

try:
    r = session.get(url, timeout=10)
    r.raise_for_status()
    return r.json()
except requests.Timeout:
    log.error("request timed out: %s", url)
    raise
except requests.HTTPError as e:
    body = e.response.text[:500]      # first 500 chars for the log
    log.error("HTTP %s on %s: %s", e.response.status_code, url, body)
    raise
except requests.RequestException as e:
    log.error("network error: %s", e)
    raise
except json.JSONDecodeError as e:
    log.error("bad JSON from %s: %s", url, r.text[:200])
    raise

Always log a snippet of the response body on errors — APIs often return JSON with a useful "message" field.

Async with httpx

When you need to fan out to many endpoints, requests is sequential per session. httpx has the same API but async-aware:

import asyncio, httpx

async def fetch(client: httpx.AsyncClient, url: str) -> dict:
    r = await client.get(url, timeout=15)
    r.raise_for_status()
    return r.json()

async def fetch_all(urls: list[str]) -> list[dict]:
    async with httpx.AsyncClient(http2=True) as client:
        return await asyncio.gather(*(fetch(client, u) for u in urls))

results = asyncio.run(fetch_all([f"https://api.example.com/items/{i}" for i in range(100)]))

For "fetch 100 things in parallel", httpx + asyncio.gather is night-and-day faster. Don't go async unless you actually need the parallelism — sync code is easier to debug.

Receiving webhooks (FastAPI)

Sometimes you're the server. Minimal webhook receiver:

from fastapi import FastAPI, Header, HTTPException, Request
import hashlib, hmac, os

app = FastAPI()
SECRET = os.environ["WEBHOOK_SECRET"].encode()

def verify(body: bytes, signature: str) -> bool:
    expected = "sha256=" + hmac.new(SECRET, body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)

@app.post("/webhook")
async def webhook(req: Request, x_hub_signature_256: str = Header(...)):
    body = await req.body()
    if not verify(body, x_hub_signature_256):
        raise HTTPException(403, "bad signature")
    payload = await req.json()
    # process payload...
    return {"ok": True}

hmac.compare_digest avoids timing-attack leaks. Reject the request fast on bad signatures — never process unverified webhooks.

Hands-on: a tiny GitHub releases scraper

Hands-on · pulls all releases of a public repo
#!/usr/bin/env python3
from __future__ import annotations
import os, time, logging, sys
from requests import Session
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

log = logging.getLogger("releases")

def make_session(token: str | None) -> Session:
    s = Session()
    s.headers["Accept"] = "application/vnd.github+json"
    s.headers["X-GitHub-Api-Version"] = "2022-11-28"
    if token:
        s.headers["Authorization"] = f"Bearer {token}"
    retry = Retry(total=5, backoff_factor=0.5,
                  status_forcelist=(429, 500, 502, 503, 504),
                  respect_retry_after_header=True)
    s.mount("https://", HTTPAdapter(max_retries=retry))
    return s

def releases(s: Session, owner: str, repo: str):
    url = f"https://api.github.com/repos/{owner}/{repo}/releases?per_page=100"
    while url:
        r = s.get(url, timeout=(5, 30))
        r.raise_for_status()
        log.debug("rate remaining: %s", r.headers.get("X-RateLimit-Remaining"))
        yield from r.json()
        url = r.links.get("next", {}).get("url")

def main(owner: str, repo: str) -> int:
    logging.basicConfig(level=logging.INFO,
                        format="%(asctime)s %(levelname)-5s | %(message)s")
    s = make_session(os.environ.get("GITHUB_TOKEN"))
    for rel in releases(s, owner, repo):
        print(f"{rel['tag_name']:<15} {rel['published_at']}  {rel['name']}")
    return 0

if __name__ == "__main__":
    raise SystemExit(main(*sys.argv[1:3]))

Run: ./releases.py torvalds linux. Pagination, retries, optional auth, structured logging — all in 30 lines.

Exercises

EX 3.1 easy Add a timeout

This call hangs forever sometimes. Fix it without changing behaviour otherwise:

r = requests.get("https://api.example.com/health")
r.raise_for_status()
Show solution 
r = requests.get("https://api.example.com/health", timeout=(3, 10))
r.raise_for_status()

Health-checks should fail fast. 3 s connect, 10 s read is a reasonable default; tune for your service.

EX 3.2 medium Retry only safe verbs

Configure a session that retries GET, HEAD, PUT, DELETE on 5xx but never retries POST. Why is the distinction important?

Show solution 
retry = Retry(
    total=5,
    backoff_factor=0.5,
    status_forcelist=(500, 502, 503, 504),
    allowed_methods=("GET", "HEAD", "PUT", "DELETE", "OPTIONS"),
)

POST typically creates a resource; retrying after a partial success creates a duplicate. PUT/DELETE are conventionally idempotent — same operation twice is the same as once. If your POST has an Idempotency-Key, it's safe to add it to allowed_methods.

EX 3.3 medium Token refresh

Build a token cache: function returns a valid token, fetching a new one only when within 30 s of expiry. Thread-safe is bonus.

Show solution 
import threading, time, requests

_lock  = threading.Lock()
_token = ("", 0.0)        # (value, expiry_ts)

def get_token() -> str:
    global _token
    with _lock:
        val, exp = _token
        if val and time.time() < exp - 30:
            return val
        r = requests.post(TOKEN_URL,
            data={"grant_type": "client_credentials"},
            auth=(CLIENT_ID, CLIENT_SECRET), timeout=10)
        r.raise_for_status()
        body = r.json()
        _token = (body["access_token"], time.time() + body["expires_in"])
        return _token[0]

Lock prevents two threads simultaneously hitting the token endpoint. The 30 s safety margin handles clock skew between client and auth server.

EX 3.4 hard Atomic streaming download

Write a function download(url, dst) that: streams the body, writes to dst.part, verifies a SHA256 you pass in, atomically renames to dst. On any failure, leave no partial file behind.

Show solution 
import hashlib, requests
from pathlib import Path

def download(url: str, dst: Path, expected_sha: str, session=None) -> None:
    s = session or requests.Session()
    tmp = dst.with_suffix(dst.suffix + ".part")
    h = hashlib.sha256()
    try:
        with s.get(url, stream=True, timeout=(10, 600)) as r:
            r.raise_for_status()
            with tmp.open("wb") as f:
                for chunk in r.iter_content(chunk_size=1 << 20):
                    f.write(chunk); h.update(chunk)
        actual = h.hexdigest()
        if actual != expected_sha:
            raise ValueError(f"sha mismatch: expected {expected_sha}, got {actual}")
        tmp.replace(dst)            # atomic
    except Exception:
        tmp.unlink(missing_ok=True)
        raise
EX 3.5 hard Async fan-out

Fetch 200 endpoint URLs concurrently with httpx, but at most 20 in flight at once. Return a list of (url, status_code) tuples.

Show solution 
import asyncio, httpx

async def fetch(sem, client, url):
    async with sem:
        try:
            r = await client.get(url, timeout=10)
            return (url, r.status_code)
        except httpx.HTTPError as e:
            return (url, str(e))

async def fan_out(urls: list[str], concurrency: int = 20):
    sem = asyncio.Semaphore(concurrency)
    async with httpx.AsyncClient() as client:
        return await asyncio.gather(*(fetch(sem, client, u) for u in urls))

results = asyncio.run(fan_out(urls, 20))

The semaphore caps in-flight requests. Without it, 200 simultaneous connections would overwhelm both your client and the server.

Recap

  • Always pass timeout= on every HTTP call. Always.
  • Use a Session for connection pooling; mount a Retry adapter for backoff.
  • Idempotency keys for unsafe POSTs that need to be retry-safe.
  • Stream big payloads (download and upload) — never load gigabytes into memory.
  • Auth: bearer tokens with caching/refresh; mTLS for service-to-service; never embed plain passwords.
  • Pagination: link-header style or cursor-token style — wrap in a generator.
  • For fan-out work, switch to httpx + asyncio.gather with a semaphore.
  • Receiving webhooks: verify HMAC signatures with hmac.compare_digest.
