Chapter 06 Automation Patterns

The patterns that turn a one-off script into something you'd run a thousand times unattended. Idempotency, retries with jitter, locks, atomic writes, structured logging, observability, signals, webhooks, scheduling. The discipline that separates "automation" from "scripts that work on Tuesdays".

Idempotency — the most important property

An operation is idempotent if running it N times has the same effect as running it once. This is what lets you safely retry, what makes "did the job actually run?" answerable from the final state alone, and what enables every reliability pattern that follows.

# NOT idempotent — appends each call
def add_user(name):
    with open("users.txt", "a") as f:
        f.write(name + "\n")

# Idempotent — checks first, ensures end state
def add_user(name):
    users = set(read_users())
    if name in users:
        return False                           # already there
    users.add(name)
    atomic_write_users(users)
    return True

# Idempotent — desired-state pattern
def ensure_promoted(artifact, channel):
    current = registry.get_channel(artifact)
    if current == channel:
        log.info("already at %s, no-op", channel)
        return
    registry.move(artifact, channel)

The right mental shift: write functions that express the desired end state ("this should exist", "this should be at channel X"), not the action ("create this", "move this"). Run twice → second run is a no-op. Run on a partially-completed previous run → it converges.

This is exactly how Kubernetes works (Chapter 7). Internalise it now.

Retries with backoff and jitter

Transient failures are inevitable in distributed systems. The good retry has three properties: exponential backoff (each attempt waits longer), jitter (avoid thundering herds), cap (don't retry forever).

import random, time, logging
from typing import Callable, TypeVar

T = TypeVar("T")
log = logging.getLogger(__name__)

def retry(
    fn: Callable[[], T],
    *,
    attempts: int = 5,
    base: float = 0.5,
    cap: float = 30.0,
    exceptions: tuple = (Exception,),
) -> T:
    """Run fn() with exponential backoff + jitter. Returns its result, raises on final failure."""
    for attempt in range(1, attempts + 1):
        try:
            return fn()
        except exceptions as e:
            if attempt == attempts:
                raise
            delay = min(cap, base * 2 ** (attempt - 1))
            delay *= random.uniform(0.5, 1.5)               # ±50% jitter
            log.warning("attempt %d/%d failed (%s), sleeping %.2fs",
                        attempt, attempts, e, delay)
            time.sleep(delay)
    raise RuntimeError("unreachable")

Or use the tenacity library — battle-tested, decorator-style:

from tenacity import retry, stop_after_attempt, wait_random_exponential, retry_if_exception_type

@retry(
    stop=stop_after_attempt(5),
    wait=wait_random_exponential(multiplier=0.5, max=30),
    retry=retry_if_exception_type((ConnectionError, TimeoutError)),
    reraise=True,
)
def fetch_artifact(name: str) -> bytes:
    return registry.download(name)

Don't blanket-retry every exception. Retry only "this might succeed if we try again": network errors, 5xx, 429. Don't retry: 4xx, validation errors, "key not found" — they'll fail the same way.

Circuit breakers — when retries make things worse

Retrying a downstream that's already overloaded prolongs the outage. A circuit breaker stops calling for a cooldown period after consecutive failures.

from dataclasses import dataclass, field
import time

@dataclass
class Breaker:
    threshold: int = 5
    cooldown_s: float = 60.0
    failures: int = 0
    open_until: float = 0.0

    def call(self, fn, *args, **kwargs):
        now = time.monotonic()
        if now < self.open_until:
            raise RuntimeError("circuit open")
        try:
            r = fn(*args, **kwargs)
            self.failures = 0                  # success resets
            return r
        except Exception:
            self.failures += 1
            if self.failures >= self.threshold:
                self.open_until = now + self.cooldown_s
                log.error("circuit opened for %.0fs", self.cooldown_s)
            raise

breaker = Breaker(threshold=5, cooldown_s=60)
result = breaker.call(do_thing)

For real services, use pybreaker or build into your HTTP client. The pattern is: protect a downstream by occasionally letting requests through to test for recovery rather than hammering forever.

Locks — never run two of me at once

If your script is on a cron and an earlier run is still running, a second run can race. Solve with a file lock:

import fcntl, sys, contextlib
from pathlib import Path

@contextlib.contextmanager
def file_lock(path: Path):
    """Block until exclusive lock is held, release on exit."""
    path.parent.mkdir(parents=True, exist_ok=True)
    f = open(path, "a+")
    try:
        fcntl.flock(f.fileno(), fcntl.LOCK_EX)        # blocks
        yield
    finally:
        fcntl.flock(f.fileno(), fcntl.LOCK_UN)
        f.close()

# Non-blocking variant — fail fast if another run is in flight
@contextlib.contextmanager
def file_lock_nb(path: Path):
    f = open(path, "a+")
    try:
        try:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)
        except BlockingIOError:
            print("already running; exiting", file=sys.stderr)
            raise SystemExit(0)
        yield
    finally:
        fcntl.flock(f.fileno(), fcntl.LOCK_UN); f.close()

# Usage
with file_lock_nb(Path("/var/lock/promote.lock")):
    do_the_work()

Cross-machine? Use Redis (redis-py + SETNX with TTL) or a distributed lock service. For a single host, flock is iron-clad.

Structured logging

For automation, JSON-shaped logs win because they're machine-parseable, ship cleanly to log aggregators, and let you query "all promote jobs to release in the last 7 days" with regular tools.

import logging, json, time, contextvars
from typing import Any

# Per-task context — survives across function calls without threading args through
ctx_request_id: contextvars.ContextVar[str] = contextvars.ContextVar("request_id", default="-")
ctx_artifact:   contextvars.ContextVar[str] = contextvars.ContextVar("artifact",   default="-")

class JSONFormatter(logging.Formatter):
    def format(self, record):
        d = {
            "ts":         time.strftime("%Y-%m-%dT%H:%M:%S", time.gmtime(record.created)),
            "level":      record.levelname,
            "logger":     record.name,
            "msg":        record.getMessage(),
            "request_id": ctx_request_id.get(),
            "artifact":   ctx_artifact.get(),
        }
        if record.exc_info:
            d["exc"] = self.formatException(record.exc_info)
        return json.dumps(d, separators=(',', ':'))

# Usage
log = logging.getLogger(__name__)
ctx_request_id.set("abc123")
ctx_artifact.set("firmware-1.0.img")
log.info("promoting", extra={"channel": "release"})
# {"ts":"2026-04-23T10:30:00","level":"INFO",...,"msg":"promoting","request_id":"abc123","artifact":"firmware-1.0.img"}

Context vars let you stick a request_id at the top of a job and have every log line include it without ever passing it as an argument. They're also async-safe, unlike threadlocals.

Or use structlog, which handles context propagation, key-value formatting, and pretty dev output vs JSON prod output natively.

Signals and graceful shutdown

Long-running automation needs to handle SIGTERM gracefully — Kubernetes sends it before SIGKILL; Jenkins sends it on cancellation; CI systems send it on timeouts.

import signal, threading

stopping = threading.Event()

def _on_term(signum, frame):
    log.info("got signal %d, finishing current item then exiting", signum)
    stopping.set()

signal.signal(signal.SIGTERM, _on_term)
signal.signal(signal.SIGINT,  _on_term)

while not stopping.is_set():
    item = queue.get(timeout=1)
    process(item)                              # finishes current work
    if stopping.is_set():
        break
log.info("clean shutdown")

The pattern: catch the signal, set a flag, finish the current logical unit of work, exit cleanly. Don't sys.exit() from the handler — it can interrupt midway through a write or a network call.

Receiving webhooks safely

Already covered in Chapter 3, but the safety checklist deserves repeating:

  1. Verify HMAC signature with hmac.compare_digest (timing-safe).
  2. Reject unknown event types instead of best-effort processing.
  3. Return 200 quickly, queue the work; webhook senders retry on slow responses.
  4. Idempotency via the event's stable ID — process events only once even if delivered twice.
  5. Reject untrusted senders by source IP allowlist or mTLS where possible.
from fastapi import FastAPI, Header, HTTPException, BackgroundTasks
import hmac, hashlib, os, json, time

app = FastAPI()
SECRET = os.environ["WEBHOOK_SECRET"].encode()
seen: dict[str, float] = {}                    # in production: Redis with TTL

@app.post("/webhook")
async def webhook(req, bg: BackgroundTasks,
                  x_signature: str = Header(...), x_event_id: str = Header(...)):
    body = await req.body()
    expected = "sha256=" + hmac.new(SECRET, body, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, x_signature):
        raise HTTPException(403, "bad signature")
    # Dedupe (cheap in-memory; replace for HA)
    now = time.time()
    for k, t in list(seen.items()):
        if now - t > 86400: del seen[k]
    if x_event_id in seen:
        return {"ok": True, "dedup": True}
    seen[x_event_id] = now

    payload = json.loads(body)
    bg.add_task(process_event, payload)        # respond 200 fast
    return {"ok": True}

Observability

Three pillars: logs, metrics, traces. For automation, logs are the headliner; metrics matter when you run the same script thousands of times.

Metrics with Prometheus

from prometheus_client import Counter, Histogram, start_http_server

PROMOTIONS    = Counter("promote_total", "promotions", ["channel", "result"])
PROMOTE_TIME  = Histogram("promote_duration_seconds", "duration", ["channel"])

start_http_server(9100)             # /metrics on :9100

def promote(artifact, channel):
    with PROMOTE_TIME.labels(channel).time():
        try:
            do_promote(artifact, channel)
            PROMOTIONS.labels(channel, "ok").inc()
        except Exception:
            PROMOTIONS.labels(channel, "fail").inc()
            raise

Prometheus scrapes :9100/metrics. You get a counter of promotions per channel, a histogram of latencies. Alert on rates and percentiles.

For short-lived jobs (cron-style), use the Pushgateway: the job pushes its final metrics to a long-running aggregator before exiting.

Testing automation

Three test layers:

  1. Unit tests — pure functions (validation, parsing, computation). Fast, no I/O.
  2. Integration tests — talk to a real Postgres / fake Artifactory in a Docker container, started by your test setup. testcontainers is excellent for this.
  3. End-to-end / smoke — run the actual CLI against a staging environment. Slower; gates releases.
from testcontainers.postgres import PostgresContainer

def test_db_migration():
    with PostgresContainer("postgres:16") as pg:
        url = pg.get_connection_url()
        run_migrations(url)
        with psycopg.connect(url) as conn:
            cur = conn.execute("SELECT 1 FROM users LIMIT 1")
            assert cur.fetchone() is not None

--dry-run as a first-class feature

Every automation that mutates state should support --dry-run: print what would happen, change nothing. Saves you the day a config typo would have nuked production.

def promote(artifact: str, src: str, dst: str, *, dry_run: bool = False):
    log.info("promote %s: %s → %s%s",
             artifact, src, dst, " (dry-run)" if dry_run else "")
    if dry_run:
        return
    registry.move(artifact, src, dst)

Bonus: have CI run integration tests in dry-run mode against production credentials, so you catch "I would have deleted the wrong thing" before it happens.

Configuration changes — review-driven, not eyeball-driven

Patterns that scale to a team:

  • GitOps for everything: cron schedules, secrets references, channel rules, all in git, all reviewed.
  • Don't make state changes from a CLI on a laptop. Make them via a CI job triggered by a merged PR. Audit log = git log.
  • Break-glass procedures for incidents — explicit, audited, time-bounded.

Hands-on: a robust promotion job

Hands-on · all the patterns in one script
pythonscripts/promote.py
#!/usr/bin/env python3
"""Idempotent promotion with retries, locking, structured logs, metrics, dry-run."""
from __future__ import annotations
import argparse, fcntl, hmac, json, logging, os, signal, sys, time
from contextlib import contextmanager
from pathlib import Path
from typing import Callable, TypeVar
import requests

log = logging.getLogger("promote")
T = TypeVar("T")

# ----- patterns -----------------------------------------------------------
def configure_logging(level: str = "INFO"):
    h = logging.StreamHandler(sys.stderr)
    h.setFormatter(logging.Formatter('{"ts":"%(asctime)s","lvl":"%(levelname)s","msg":"%(message)s"}'))
    logging.basicConfig(level=level, handlers=[h])

@contextmanager
def file_lock_nb(path: Path):
    path.parent.mkdir(parents=True, exist_ok=True)
    f = open(path, "a+")
    try:
        try:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)
        except BlockingIOError:
            log.info("another instance running, exiting"); raise SystemExit(0)
        yield
    finally:
        fcntl.flock(f.fileno(), fcntl.LOCK_UN); f.close()

def retry(fn: Callable[[], T], *, attempts=5, base=0.5, cap=30.0,
          exc=(requests.RequestException,)) -> T:
    import random
    for i in range(1, attempts + 1):
        try:
            return fn()
        except exc as e:
            if i == attempts: raise
            d = min(cap, base * 2 ** (i - 1)) * random.uniform(0.5, 1.5)
            log.warning("attempt %d failed (%s); sleep %.2fs", i, e, d)
            time.sleep(d)
    raise RuntimeError("unreachable")

# ----- domain --------------------------------------------------------------
def already_promoted(client, artifact, channel) -> bool:
    info = retry(lambda: client.get_artifact(artifact))
    return info.get("channel") == channel

def promote(client, artifact: str, src: str, dst: str, *, dry_run: bool):
    if already_promoted(client, artifact, dst):
        log.info("idempotent no-op: %s already at %s", artifact, dst); return

    log.info("promoting %s: %s -> %s%s",
             artifact, src, dst, " (dry-run)" if dry_run else "")
    if dry_run: return

    retry(lambda: client.move(artifact, src, dst))
    log.info("promoted ok")

# ----- entry --------------------------------------------------------------
def main(argv=None) -> int:
    p = argparse.ArgumentParser()
    p.add_argument("artifact")
    p.add_argument("--from", dest="src", required=True)
    p.add_argument("--to",   dest="dst", required=True)
    p.add_argument("--dry-run", action="store_true")
    args = p.parse_args(argv)

    configure_logging(os.environ.get("LOG_LEVEL", "INFO"))
    signal.signal(signal.SIGTERM, lambda *_: sys.exit(143))

    client = make_client(os.environ["NEXUS_URL"], os.environ["NEXUS_TOKEN"])
    with file_lock_nb(Path(f"/var/lock/promote-{args.artifact}.lock")):
        try:
            promote(client, args.artifact, args.src, args.dst, dry_run=args.dry_run)
            return 0
        except requests.HTTPError as e:
            log.error("HTTP %s: %s", e.response.status_code, e.response.text[:200])
            return 1

if __name__ == "__main__":
    raise SystemExit(main())

It's all here: idempotency check before action, retry with jitter, file lock to prevent overlap, JSON logs, signal handler, env-based config, --dry-run, distinct exit codes. About 80 lines.

file_lock_nb from above. The non-blocking flag LOCK_NB raises BlockingIOError immediately rather than waiting; we catch it and exit gracefully.

EX 6.3 medium Jitter math

Compute the wait sequence for base=0.5, cap=30, 6 attempts, jitter ±50%. Why is jitter important?

Show solution

Without jitter: 0.5, 1, 2, 4, 8, 16. With jitter, each multiplied by a random factor in [0.5, 1.5]: e.g. 0.32, 1.20, 1.78, 4.40, 6.10, 21.0.

If 100 clients all hit the same downstream and all retry without jitter, they crash into the server at the same instant on every attempt — a thundering herd. Jitter spreads the load and lets the server actually recover.

EX 6.4 hard Graceful shutdown

Write a worker loop that processes items from a queue but, on SIGTERM, finishes the current item, flushes a final metric, then exits with code 0. Demonstrate it doesn't drop work.

Show solution 
import signal, queue, threading, time

stop = threading.Event()
signal.signal(signal.SIGTERM, lambda *_: stop.set())
signal.signal(signal.SIGINT,  lambda *_: stop.set())

q: queue.Queue[str] = queue.Queue()

def worker():
    while True:
        try:
            item = q.get(timeout=0.5)
        except queue.Empty:
            if stop.is_set(): break
            continue
        process(item); q.task_done()
        if stop.is_set(): break
    flush_metrics()
    log.info("clean exit")

worker()

Key idea: signal sets a flag; loop checks it at safe boundaries (between items), never mid-item.

EX 6.5 hard Webhook with idempotency

Extend the FastAPI webhook handler to dedupe events using their id field, persisted to disk so dedup survives restarts. Handle the dedup-store growing forever.

Show solution

Use a SQLite database with a TTL'd table:

import sqlite3, time

DB = sqlite3.connect("/var/lib/webhook/seen.db", check_same_thread=False)
DB.execute("CREATE TABLE IF NOT EXISTS seen (id TEXT PRIMARY KEY, ts INTEGER)")

def seen_already(event_id: str, ttl: int = 7 * 24 * 3600) -> bool:
    now = int(time.time())
    DB.execute("DELETE FROM seen WHERE ts < ?", (now - ttl,))   # GC
    cur = DB.execute("INSERT OR IGNORE INTO seen VALUES (?, ?)", (event_id, now))
    DB.commit()
    return cur.rowcount == 0          # 0 means it was already there

SQLite gives ACID guarantees on a single host. For multi-host, use Redis with SETNX + TTL.

Recap

  • Idempotency is the foundation. Write functions that express end state, not actions.
  • Retries with exponential backoff and jitter; cap attempts; only retry transient errors.
  • Circuit breakers prevent retry storms during downstream outages.
  • File locks (fcntl.flock) for single-host single-instance; Redis or a real lock service for cross-host.
  • Atomic writes for state files (Chapter 2 idiom).
  • Structured (JSON) logs with context vars for trace IDs.
  • Trap SIGTERM, set a flag, finish current work, exit 0.
  • Webhooks: verify HMAC, dedupe by event ID, return 200 fast.
  • Metrics for any automation that runs >100 times/day.
  • --dry-run for everything that mutates state. Always.
